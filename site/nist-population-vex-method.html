Operating facts → source expression → VEX

  1. Select an identified BOM component–CVE pair, asset type and exact deployed instance. Bind inventory/configuration records to the same build, baseline, origin, observation time and validity period. Asset type supplies context, not a verdict.
  2. The server matches the source product and asks deployment, the actual running version and only translated conditions relevant to that product/CVE. Optional NIST material retains all 54 source items and 167 collection details with English evidence.
  3. Selected enums are mapped by server-owned adapters to three-valued conditions. Source AND/OR/NOT relationships are preserved. Unobservable attacker credentials, ambiguous subjects and unsupported condition text stay unknown.
  4. The engine validates evidence, product/version membership, scope and the expression. It saves the selected facts, computed values, source pointers and final trace. There is no external network or LLM call in the experiment.
Computed statusRequired facts
affectedDeployment is verified, the exact observed running version matches a source affected status and the source-derived operating formula is true.
fixedThe observed running version matches an explicit source fixed status, or a supported manufacturer-specific fixed-release rule. A recommended release or first_fixed entry alone is not extrapolated into an open-ended range.
not_affectedComplete scoped inventory establishes component absence; or the source explicitly marks the observed release unaffected. A configuration-negative finding additionally requires an exhaustive source-specific rule; the population compiler does not claim exhaustive configuration coverage.
under_investigationMissing, conflicting or expired evidence; unbound product/version; unsupported comparison; unresolved source identity/condition; or a non-exhaustive negative operating path. Being outside a known-affected range does not establish a fix.

Example outside the earlier eight adapters: CVE-2011-4051 · InduSoft Web Studio 6.1 asks deployment, running version and source-described remote reachability. With verified affirmative facts the server calculates affected. A blocked recorded path stays under investigation because extraction does not establish that every attack path is covered.

Full-population experiment

Each CVE receives source_present, component_absent and evidence_missing cases. Original CSAF status pointers and a separate reference version interpreter supply labels, not the evaluator's output. The source_present label declares all latent source prerequisites satisfied in the synthetic world; inputs expose only the facts the operating adapters can represent. Untranslated facts are withheld, so an affected reference may correctly lead the cautious engine to abstain.
