How Precision was calculated

Precision = TP / (TP + FP)

Precision is the proportion of positive outputs that match the gold labels. Missed positives are false negatives and affect Recall. Zero outputs do not count as 100% Precision or a passing result.

#3 · Score every output CVE mapping

Gold labels are atomic CPE mappings for product, version and edition. One SBOM may map to multiple CVEs, so the true-positive count may exceed the CVE population. Every output mapping was compared, rather than checking only one target CVE.

The primary metric is the conservative lower bound. Only the 16 unresolved mappings actually output were counted as false positives; the entire set of 2,670 unresolved CVEs was not added. This full-population check includes training-related inputs and must be distinguished from independent test performance.

#4 · Treat affected outputs as positive

In the synthetic world, a true impact produces a true positive and a false impact produces a false positive. The raw model and model plus validation logic were scored separately. Validation defers a decision when observations are missing, conflicting or expired, or evidence is insufficient.

How synthetic SBOMs and gold labels were constructed

#3 · Inject one error type into each control

A total of 145,204 source entries from 10,847 CVEs with CPEs were organized into 50,860 product/version-range conditions. CPE vendor, product, version and type were transferred to SBOM fields. Missing version evidence remained NOASSERTION. The original CPE was retained in metadata.component.cpe.

One control and one perturbed SBOM were created for each condition, producing 101,720 source SBOMs. Each perturbation uses one error type: a missing or misspelled name, a missing or reformatted version, or a missing CPE or altered prefix. The notation of the same asset was changed without substituting another product/version. Examples: controller → ocntroller, 3.1.4 → v3.1.4, cpe: → CPE:.

Because only one field was changed, a version may remain inside the CPE even if the version field is removed. This tests identification using the remaining evidence. The H200 full-population run separately selected one fixed representative unperturbed control for each CVE; it did not evaluate the complete perturbation set.

#4 · Generate fictional operating states from real CVE conditions

For each of 2,452 CVEs with enough conditions to construct a conditional world, six states were created: conditions true, conditions false, two kinds of missing key observations, conflicting observations and expired observations. Gold labels were calculated by a separate Boolean simulator. Each of the 9,966 CVEs with insufficient source conditions retained one deferred case.

2,452 × 6 + 9,966 = 24,678 cases

Inputs and labels are separate files. Labels were not sent to the model. The gold generator and predictor are separate code, but share source material and draft conditions. Independent review of source meaning and validation of actual industrial asset impact remain incomplete.
