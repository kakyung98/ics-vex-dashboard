# 14B 데이터 감사·재학습 실험 (2026-11-19)

목표는 인용·원자 조건 문장·유형·주체·필요성을 함께 맞추는 정확 일치 F1 0.90이다. 기존 metrics 함수를 변경하지 않았다. 유형·주체·필요성 오류가 인용 일치만으로 통과하지 않는 회귀검사를 추가했다.

전체 12,759개 문서(학습 8,931 / 개발 1,914 / 테스트 1,914)를 감사 ledger에 보존했다. 원본 분할·교사 파일 해시를 audit.zip에 고정했다. 감사의 오류 의심 표시는 확정 정답이나 삭제 지시가 아니다. 학습 88개·개발 34개·테스트 16개 문서에서 유형 충돌·인증 유형 오분류·수정 지시의 조건 오인·검증 문턱 불일치 등이 발견됐다.

기존 학습은 positive 문서 219개/사실 323개뿐이었고, n=0과 n=2를 전부 버렸다. 학습 원천의 불확실 후보 275개 및 명시적 불필요 후보 149개가 표적에서 사라졌다. 소스 문장 함의 NLI는 조건 유형·주체·필요성 정답을 보증하지 않는다. 기존 개발 성능은 학습 손실이 줄어도 개선되지 않아 데이터와 표적 정의를 먼저 점검한다.

새 실험은 H200의 별도 namespace condition-14b-repair-20261119-r3에서 실행한다. 기존 어댑터를 덮어쓰거나 운영 VEX에 배포하지 않는다.

1. 학습 문서 8,931건 전부를 원문과 대조해 기계 표적을 재검토한다. 기존 후보는 불신 입력이며 의미가 옳은 경우에만 기존 문장을 보존한다. n=0/1/2를 구분한다.
2. 원문 인용 위치, 유형·주체, 동일 문장의 상충 표적, 수정 지시/영향/버전 오분류를 검사하고 원문 전체·인용 NLI 및 별도 검토를 보존한다. 이 자동 재표지는 독립 전문가 정답이 아니다.
3. 수정에 실패한 문서를 음성으로 바꾸지 않는다. 모든 문서를 ledger에 보존한다. 특히 이전에 지도 표적이 있던 어려운 문서가 재검토 후 미확정이면, 그것을 빼고 쉬운 데이터로 학습하지 않고 training_quality_gate에서 원문 판정을 요구한다.
4. 데이터 품질 게이트가 통과하면 새 14B LoRA를 학습한다(최대 12 epoch, lr 2e-5). 개발셋의 기존 주 지표만으로 체크포인트를 고르고 테스트는 선택 후 평가한다.
5. 개발/테스트 원본 참조와 평가 함수 해시를 고정하고 검사한다. 기존 테스트는 1,914개 중 참조가 있는 189개를 점수화할 수 있으며, 미라벨 1,725개를 음성으로 바꾸지 않는다. 이 기존 참조에는 n=0/2 정답이 빠져 있어 필요성 전체의 의미 정확도를 증명할 수 없다. 전체 의미 정확도 주장은 원문 기반 별도 정답 검토가 필요하다.

현재 90% 달성 결과는 없다. 단계별 상태는 repair_status.json, 수정 내역은 원격 repaired_train_v2.jsonl, 게이트와 훈련 결과는 별도 JSON에 남는다. 잘못된 평가 라벨도 주석 없이 덮어쓰지 않는다. 향후 정답을 교정할 때는 원본과 정정본의 차이 및 같은 평가 기준의 결과를 나란히 보고해야 한다.

```powershell
python -X utf8 tools/run_condition_14b_repair.py collect --variant r3
python -X utf8 -m pytest tests/test_condition_dataset_audit.py tests/test_condition_14b_training.py -q
```
