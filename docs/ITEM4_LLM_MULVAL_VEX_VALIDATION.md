# #4: 원문 → 14B 조건 후보 → MulVAL → 자산 운영 정보 → VEX

> 과거 NLI 기반 실험의 연구 기록이다. 이 문서의 NLI 검증기·overlay·전용 실행기는 2026-11-19 정리에서 제거했다. 현재 실행·판정 정책은 [VEP 계약](VULNERABILITY_EXPLOITATION_PREREQUISITE.md), [컴포넌트 흐름](COMPONENT_VEX_WORKFLOW.md), [역할별 어댑터 학습](PREREQUISITE_ROLE_TRAINING_DATA.md)을 따른다. 아래 과거 성능·분할·판정을 현재 시스템의 결과로 사용하지 않는다.

이 문서는 구현과 검증의 범위를 구분한다. MulVAL의 도출 기록은 제출한 규칙에서 결론이 따라옴을 확인한다. 원문을 잘못 해석한 규칙 자체를 MulVAL이 교정하지는 않는다. 따라서 추출·범위·관계 검증을 그래프 생성 앞에 둔다.

## 근거의 역할

- CVE별 공급사 원문: 악용 또는 영향 조건, 필요성, AND/OR, 부정, 제품·버전 범위의 근거.
- 자산 유형: 수집할 자산 운영 정보의 안내. 유형만으로 네트워크 접근, 기능 활성화, 인증·권한을 참/거짓으로 만들지 않는다.
- NIST SP 800-82 Rev.4 IPD, Tables 12–17: 자산 운영 정보 수집 항목의 근거. 54개 원문 행과 167개 프로젝트 세부 항목을 구분한다. 이는 초안에 대한 버전 고정 매핑이며, NIST가 CVE별 VEX 판정을 정한 것은 아니다. 공식 문서: https://csrc.nist.gov/pubs/sp/800/82/r4/ipd
- 실제 운영기록: 해당 구성요소 인스턴스·버전·설정 기준선·운영 모드·접근 출발점·유효기간 안에서 조건을 평가하는 근거.
- MulVAL/XSB: 원문에 연결된 규칙의 실제 유도 구조. 자산 간 전이나 성공한 공격을 임의로 만들지 않는다.

## 추출 출력의 검증

각 후보는 source ID, 원문 SHA-256, 정확한 인용 및 시작/끝 위치, 원자 조건 문장, 유형, 주체, 필요성을 보존한다. quote ID는 현재 원문의 인용 카탈로그 안에서만 선택하도록 JSON 문법을 제한한다. 문법 통과와 정확한 문자열 일치는 의미 정확도가 아니다.

1. 인용이 해당 CVE 원문과 해시에 정확히 맞는지 확인한다. 다른 CVE·제품의 공통 문맥을 전용 근거로 승격하지 않는다.
2. 정방향 추출과 역방향 검토를 비교한다. 인용이 요구·필요성을 실제로 지지하는지, 결과·패치 설명·일반 권고를 조건으로 오인하지 않았는지 검토한다.
3. content, necessity, actor, polarity, scope를 각각 검토한다. 예: 커널 수정 설명의 “We need to check …”는 공격자 필요조건으로 받아들이지 않는다.
4. 전체 문맥과 인용만을 전제로 한 별도 DeBERTa NLI를 모두 확인한다. entailment 점수 0.90은 공학적 수용 문턱이며 ICS 정확도 90%라는 뜻이 아니다. 필요성 검토를 NLI로 대체하지 않는다.
5. 조건 간 AND/OR 관계는 별도 원문 인용과 관계 검토가 있어야 한다. 검증되지 않은 조건이나 관계는 unknown/gap으로 남긴다.
6. 공급사 문서의 제품 제목·원문 포인터·문서 해시·제품 키를 확인한다. 버전은 각 경로의 제품 행에 대해 별도로 대조한다. 모호한 제목을 전체 제품의 조건으로 확장하지 않는다.
7. 운영자가 확인할 수 있는 항목만 질문으로 변환한다. 공격자의 숨은 권한·토큰 보유나 내부 메모리 상태처럼 적절한 관측 어댑터가 없는 조건은 unknown으로 유지한다.

`src/llm_source_rules.py`는 저장된 검토 결과도 현재 원문·정책으로 재검사한다. 원문이나 제품 범위 근거가 바뀌면 기존 추출을 재사용하지 않는다. `tools/run_condition_14b_pipeline.py`가 선택한 14B 어댑터의 추출과 기반 모델 검토, DeBERTa 검토를 연결한다. 동일 기반 가중치의 검토는 독립적인 전문가 검증으로 표시하지 않는다.

## MulVAL 논리와 unknown

각 원자 조건은 명시적 true/false 두 극성으로 컴파일한다. unknown은 두 극성 모두 운영 근거로 확인되지 않은 상태다. 조건 누락을 false로 바꾸지 않는다.

- AND: 모든 입력이 true이면 true, 하나라도 false이면 false, 나머지는 unknown.
- OR: 하나라도 true이면 true, 모두 false이면 false, 나머지는 unknown.
- NOT: 명시적인 반대 극성을 요구한다. unknown의 NOT도 unknown이다.

구조 생성 입력의 양극성 placeholder는 자산 운영 정보가 아니다. 실제 MulVAL CSV의 모든 규칙·전제·결론·간선을 검사하고, 이후 검증된 관측으로 그래프를 평가한다. 생성 실패 시 자체 그래프를 대신 표시하지 않는다.

전체 카탈로그는 12,418개 CVE를 제외 없이 생성한다. 제품별 경로는 서로 다른 scope guard로 분리한다. 원문 조건을 해석하지 못한 CVE도 실제 MulVAL 미확정 노드와 규칙을 갖지만, 이것을 유효 조건 추출 성공으로 집계하지 않는다. 모든 미관측 자산은 unknown이다.

대량 실행용 런타임 수정은 `tools/mulval_population_runtime.patch`에 있다. 규칙 수·파서 줄 길이 제한을 늘리고, completeTrace2의 자식 증명 존재 여부를 signed fact 단위로 table하여 동일한 조합 기록의 폭증을 제거한다. 원본 MulVAL 설치를 유지한다. 실제 CVE 4개의 노드·규칙·간선 및 270개 3값 입력 조합이 원본과 일치하고, 32개 대안 경로 스트레스에서도 모든 규칙이 보존되는지 확인했다. 이는 의미 정확도 평가가 아니다.

## 판정과 설명

| 상태 | 필요한 근거 |
|---|---|
| affected | 제품·실행 버전·배포 범위가 확인되고, 원문에 연결된 취약 조건 경로가 운영 근거로 충족됨. 실제 공격 성공이나 침해를 주장하지 않음. |
| not_affected | 완전한 범위의 미배포 근거, 공급사의 명시적 비영향 버전, 또는 완전한 원문 경로 집합의 모든 경로를 차단하는 현재 운영 근거. 불완전한 추출에서는 경로 부재를 증명하지 않음. |
| fixed | 실제 실행 버전에 공급사 근거가 있는 수정이 포함됨. 외부 통제만으로 fixed를 만들지 않음. |
| under_investigation | 출처·식별·버전·관측·관계·필요성·운영 어댑터가 미확정, 충돌하거나 유효기간을 벗어남. |

완화 전 affected 상태는 보존한다. 완화 후의 실제 조건과 효과 검증 기록을 별도로 받고 전체 경로를 다시 평가한다. 완전한 경로 차단이 입증되면 그 운영 범위의 not_affected로 기록한다. 취약 버전이 고쳐졌다고 표시하지 않는다. OpenVEX 상태 의미: https://github.com/openvex/spec/blob/main/OPENVEX-SPEC.md#status-labels

각 평가에는 원문 인용·해시, NIST 수집 행, 선택한 운영기록 원문·해시·범위·기간, 버전 멤버십, 경로 범위, 실제 MulVAL 규칙절·전제·결론, 값과 unknown 이유, 전/후 그래프 및 판정 근거를 보존한다. 자산이나 근거가 바뀌면 입력·계획 해시가 달라져 재평가해야 한다. OpenVEX/CycloneDX는 같은 정규 판정을 내보낸다.

## 14B 목표와 검증의 한계

18 epoch의 Qwen2.5-Coder-14B-Instruct LoRA 실험에서 개발셋으로 체크포인트를 선택하고 고정 테스트를 평가한다. 모델 변경에 테스트 결과를 쓰지 않는다. 분할은 공유 CVE·문서·정규화 텍스트를 묶어 분리했지만, 이 테스트셋은 이전 실험에서 사용되어 새로운 블라인드셋은 아니다.

학습 8,931개 중 양성 219개·약한 음성 1,022개만 지도 표적으로 사용한다. 7,690개 미라벨 항목을 음성으로 바꾸지 않는다. 개발 평가는 118개, 테스트 평가는 라벨이 있는 189개 전부다. 테스트의 미라벨 1,725개는 별도 ledger에 보존하며 정확도 분모에 넣지 않는다. 전체 그래프 생성 모집단 12,418개는 이 평가 분할과 별개이고 제외하지 않는다.

주 지표는 인용·원자 조건 문자열·유형·주체·필요성의 정확 일치 F1이다. slot F1과 인용 구간 F1을 별도로 보고하고 높은 구간 점수로 주 지표 90% 달성을 대체하지 않는다. 문자열 지표는 타당한 의역에도 불이익이 있으며, 자동 교사 표적 자체에 잘못된 필요조건이 발견되었다. 따라서 이 지표조차 독립적인 의미 정확도는 아니다.

90% 미달 어댑터는 기본 추출 카탈로그로 승격할 수 없다. 실험 산출물은 experimental_sources에 보관한다. 최종 의미 정확도 90%를 주장하려면 별도 전문가가 CVE 원문으로 인용 적합성·원자성·유형·주체·필요성·범위·AND/OR·누락을 판정한 고정 정답셋과 오류 분석이 필요하다. 단위 테스트, NLI 점수, 자동 교사 일치율, 그래프 생성률을 그 대신 쓰지 않는다.

## 2026-11-19 확인 결과

전수 실행 및 독립적인 아티팩트 대조를 완료했다. 12,418 CVE, 692,480 노드, 673,610 간선, 355개 원본 batch receipt를 보존한다. 원문 인용 40,023건의 위치·해시를 검사했다. 후보 원문 경로가 있는 CVE는 5,905개, 해석한 경로 없는 미확정 그래프는 6,513개, NIST 운영 항목이 연결된 CVE는 2,157개다. 모든 미관측 그래프의 결론은 unknown이다. 무결성 검사 성공은 추출 누락이나 의미 오류가 없다는 보증이 아니다.

14B 고정 테스트 주 지표는 11.90%, slot F1 70.22%, 인용 구간 F1 83.41%로 90% 목표 미달이다. 실제 원문 10개/4 CVE의 36 후보에서 자동 수용 0개이며 기본 추출기는 변경하지 않았다. 자동 교사 오류와 필요성 표지 검사의 과도한 보류 사례를 `results/condition_14b_20261119/failure_analysis.json`에 기록했다. 미달 결과와 실패 후보를 제외하지 않고 보존했다.
