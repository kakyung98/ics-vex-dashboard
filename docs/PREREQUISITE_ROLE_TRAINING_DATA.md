# VEP 및 운영 기록 대조 어댑터: 데이터 준비 계약

2026-11-19. 사용자가 실제 운영 기록을 보유하지 않는다고 확인했다. 역할별 어댑터 라우팅을 분리했으며, 신규 데이터 생성과 무결성·정답 스키마 검수가 완료됐다. 학습·평가는 `results/role_adapters_20261119_v2/`에서 추적한다. 학습 완료 여부는 실제 `training_complete.json`, 평가 완료 여부는 `evaluation/report.json`으로 확인한다. 전용 어댑터는 검증 전까지 비활성 상태다.

## 확정 데이터 v7

- 경로: `benchmark/prerequisite_roles_20261119_v7/`. 확인된 CVE 12,418개가 두 역할 각각에 실제 입력·정답 쌍으로 존재한다. 원문 전체 레코드는 `source_snapshot.jsonl`에 보존한다.
- 각 역할의 train/dev/test는 8,692/1,863/1,863개다. 원문 문서·텍스트를 공유하는 CVE 연결 그룹이 분할을 넘지 않는다. 별도 제품군 단위 독립 시험은 아니다.
- VEP 자동 주석: 조건 후보 5,745개, 시나리오 1,938개, 제품 키까지 연결된 시나리오 7개, V1 원문 제품 상태 주장 9,080개. 한 CVE에서 선택한 원문 하나·등록 제품 최대 하나의 범위이며, 모든 제품과 경로를 완전히 주석한 데이터가 아니다.
- 제품 연결이 미확정인 원문 시나리오는 `product_keys=[]`, `product_binding=unresolved`로 보존하고 실행 경로로 컴파일하지 않는다. 원문 조건을 확보하지 못한 CVE도 제거하지 않고 미해결 정답을 갖는다.
- 운영 기록: true 3,104개, false 3,107개, unknown 6,207개. 원문 기반 관측 가능한 후보가 없으면 `synthetic_conditional_atom_not_a_cve_prerequisite`인 가상 조건으로 대조 과제만 만든다. 이를 해당 CVE의 실제 선행조건으로 주장하지 않는다.
- VEP 정답은 기존 원문 규칙·제한된 패턴으로 만든 weak reference이며 전문가 Gold가 아니다. 합성 기록의 정답은 명시된 잠재 상태·시점·범위를 기준으로 한다.
- 제품 연결 시나리오는 TRAIN 1개, DEV 5개, TEST 1개다. 조건이 있는 CVE는 각각 2,876/848/848개다. 현재 주석은 eq/expected=true/direct_evidence/pending을 사용하며 NOT은 논리식에 별도로 보존한다. 다른 operator·expected·근거 직접성의 독립 성능을 이 데이터만으로 검증하지 못한다. 분포는 `results/role_adapters_20261119_v2/data_label_coverage.json`에 기록한다.
- `integrity_audit.json`은 전체 모집단·양 역할 사례·원문 그룹 격리·해시를 검사한다. `target_schema_audit.json`은 두 역할 총 24,836개 정답의 입력별 JSON 스키마 검사를 기록한다.
- V1~V7, operator/expected/necessity, 근거 직접성·검토 상태를 보존한다. V1은 운영 조건 노드와 별도다. 조건값과 제품 VEX 상태를 혼용하지 않는다.

## 고정 학습·평가 절차

동일한 해시의 Qwen2.5-Coder-14B 기저 모델에 각각 독립적인 rank 4 LoRA 어댑터를 만들고, 각 역할의 TRAIN 8,692개를 모두 한 번 학습한다. 초기에는 4비트 QLoRA로 역할별 102개를 처리한 체크포인트를 만들었다. H200 독점 잠금 확보 후에는 같은 고정 4비트 가중치를 BF16 선형 계층으로 펼쳐 고정한 상태에서 학습을 이어간다. 기저 가중치를 학습하지 않으며 최종 평가는 원래 고정된 4비트 기저 모델로 실행한다. 수치 표현 전환의 TRAIN 접두부 점검과 자원 변경은 `base_representation.json`, `resource_adjustment.json`, `frozen_run.json`에 기록한다. 이 점검은 정확도 평가가 아니다.

TEST 정답은 최적화에 사용하지 않는다. 입력 초과·메모리 문제 때문에 CVE나 토큰을 조용히 누락하지 않는다. 체크포인트에는 역할별 진행 위치·옵티마이저·난수 상태를 보존한다. 자원 조정 후에는 최대 배치 8, 배치당 최대 32,000 입력/출력 토큰을 사용하며 동일한 3% warmup/cosine 일정을 처리 사례 수로 계산한다.

최종 고정 체크포인트로 각 역할의 TEST 1,863개 전체를 평가한다. 생성 시 운영 런타임과 같은 JSON 스키마 제약을 사용한다. 출력 실패·잘못된 JSON도 전체 분모에 남긴다. VEP는 자동 주석에 대한 조건·관계 일치와 출처 검증, 운영 기록은 합성 정답에 대한 혼동행렬·클래스별 정밀도/재현율/F1을 기록한다. 평가 결과를 보고 이 시험 집합에 맞춰 재학습하거나 체크포인트를 고르지 않는다. 독립 전문가·실제 자산 정확도와 `Precision_exploitable > 0.90` 달성을 주장하지 않는다.

## 역할과 정답

| 역할 | 입력 | 지도 학습 정답 |
| --- | --- | --- |
| exploitation-prerequisites | CVE·제품별 공급사/ICSA/CSAF 원문, 정확한 문단 ID | 검토된 VEP 조건, 제품 키, AND/OR/NOT, 증거 ID, 비필수·미확정 사항 |
| operating-record-review | 검토된 양의 조건 원자, 자산·버전·구성·시간·접근 출발점 범위, 원본 기록 | 기록별 true/false/unknown, 근거 기록 ID, 현재 적용 상태·범위 일치 여부 |

운영 기록 대조의 정답은 조건값이다. affected/not_affected/fixed를 이 어댑터의 정답으로 사용하지 않는다. 최종 VEX는 버전·배포·그래프 평가 코드가 결정한다.

## 실제 기록이 없는 초기 데이터 구성

1. 로컬 공개 CVE 원문 묶음을 후보 집합으로 사용한다. 원문이 있다는 것과 검토된 VEP 정답이 있다는 것을 구분한다.
2. 원문이 명시한 제품별 전제를 주석하고 정확한 인용·논리 관계·비필수와 미확정 항목을 검토한다. LLM 제안은 검토 전 Gold로 부르지 않는다. 어려운 CVE는 미확정 상태로 보존한다.
3. 검토한 조건에 대해 동일 자산·버전·구성·시점의 잠재 상태를 명시적으로 설정하고 운영 기록을 합성한다. 정답은 그 잠재 상태와 공개된 근거로 만들며, 학습 모델의 답을 정답으로 복사하지 않는다.
4. 기록에는 현재 적용 상태, 명시적 불충족, 미관측, 과거 기록, 미래 계획, 미적용 변경, 다른 장비·버전·모드·접근 출발점, 충돌·불완전한 범위를 포함한다. unknown을 충분히 포함한다. 부정은 완전한 범위의 부재 근거가 필요하다.
5. 자연어 변형을 추가하면 변형이 상태·시점·범위·부정을 보존했는지 별도 검토한다. 공급사 권고문이나 매뉴얼을 현재 설치·적용 기록으로 바꾸지 않는다.

모든 합성 기록에는 synthetic=true, 생성 규칙·잠재 상태·범위, 생성 이력과 해시를 별도 정답 원장에 보존한다. 모델 입력에 정답·잠재 상태·상태를 암시하는 파일명이나 ID를 넣지 않는다. 테스트 정답은 모델이 접근하지 않는 파일에 분리한다.

## 분할과 평가

- 변형을 만들기 전에 CVE·공유 원문 문서·텍스트를 연결한 그룹으로 train/dev/test를 분리한다. 같은 원문의 언어 변형이나 동일 잠재 상태의 기록은 분할을 넘지 않는다. 현재 분할은 별도 제품군 holdout을 보장하지 않는다.
- 과거 동결 시험이나 디버깅에 사용한 사례는 새 독립 시험으로 포장하지 않는다. 기존 전체 CVE 모집단과 불확실성 원장은 유지한다.
- VEP는 조건 추출·정확 인용·제품 연결·필수/비필수 구분·논리식·누락을 각각 평가한다.
- 기록 대조는 true/false/unknown 별 정밀도·재현율, true→false 오류, 과거·계획을 현재로 오인하는 오류, 범위 오류, 보류율을 평가한다.
- 합성 시험 통과는 실제 OT 운영 기록 정확도나 완전한 악용조건 추출을 입증하지 않는다. 실제 기록 확보 시 별도 비식별화·검토 시험을 추가한다.

## 설정과 활성화 상태

`data/prerequisite_adapter_roles.json`에 서로 다른 전용 디렉터리·별칭을 선언했다. 두 역할은 training_in_progress이며 enabled=false다. 현재 서비스 실행은 명시적으로 기저 모델 문맥을 사용한다. 학습·평가 결과를 확인하기 전에는 완성된 전용 어댑터로 표시하지 않는다.

전용 학습이 끝나면 각 디렉터리에 역할, 실제 optimizer_updates, 가중치 해시, 학습 manifest 해시, 기저 모델 경로를 담은 training_complete.json이 필요하다. 런타임은 역할·기저 모델·가중치를 검사하고, 잠금 안에서 해당 어댑터를 선택한 뒤 성공·실패 모두 기존 식별 어댑터를 복원한다. 같은 가중치를 두 역할에 중복 활성화하거나 기존 식별 어댑터의 이름만 바꿔 활성화하지 않는다.

다운로드한 산출물은 `tools/install_prerequisite_role_adapters.py`로 설치한다. 양 역할의 학습 8,692개·평가 1,863개 완료, 평가 체크포인트 해시, 학습 원장 해시, 로컬 기저 모델의 실제 파일 해시를 확인한다. 원격 기저 경로는 동일한 가중치의 로컬 경로로 바꾸며, 원본 메타데이터와 import_receipt.json을 함께 보존한다. 기본 설치는 비활성 상태이며 `--activate`는 검증한 두 어댑터를 현재 서비스에 연결한다.
