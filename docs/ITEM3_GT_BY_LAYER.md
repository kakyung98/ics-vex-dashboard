# #3 Ground Truth를 L2/L3/L4로 분해한 결과

`python tools/tag_gt_problem_layers.py` → `data/cpe_match_eval_layered.jsonl`, `results/gt_problem_layers.json`

## 1. 계층 지침 (레코드에 이미 있는 권위만 읽음, 새로 판단하지 않음)

| 태그 | 조건 |
|---|---|
| **L2** | 어드바이저리 벤더가 이 CVE에 NVD 제품을 2개 이상 앵커 (`_ambiguous_product`) → **이름**이 제품을 갈라야 함 |
| `L2-exposed` | 위 + 컴포넌트에 CPE도 없음 → 이름이 유일한 경로 |
| **L3** | 버전 축이 이 쌍을 결정 — 음성 계열 `version`, 또는 `version_match`가 True/False |
| `L3-undecidable` | `version_match=None` — CISA가 상한만 공표해 영향 버전을 확정 못 함 |
| `L3-notation` | CISA 범위 문자열에 순서 비교 가능한 버전이 없음 (`6.1\|SP1`, `>=CPR9-SR1`) |
| **L4** | 식별자 축이 결정 — 음성 계열 `vendor`(공유코드 CVE의 타벤더 제품), 또는 `vendor_match=False` |
| `L4-absence` | 컴포넌트에 CPE도 purl도 없음 → 비교할 식별자 자체가 없음 |

## 3. 진단 — 현행 0.9490은 L2·L4를 한 쌍도 포함하지 않는다

`tools/eval_cpe_match_precision.load_gt()`가 채점 전에 버리는 것:

```
conflict        430      (두 권위 충돌)
_ambiguous_product  25,116   ← L2 전부
_negative_family=vendor  4,249   ← L4 전부
--------------------------------
채점 대상        12,073
```

남은 12,073쌍의 계층 구성:

| | 쌍 |
|---|---:|
| **L2** | **0** |
| **L3** | **3,348** |
| **L4** | **0** |
| 무축 | 8,725 |

즉 **precision 0.9490(TP 10,653 / FP 572)은 사실상 "L3 + 무축" 슬라이스의 값**이고,
연구가 해결 대상으로 내건 L2·L4에 대해서는 **측정값이 존재하지 않는다.**
L2를 뺀 이유(제품 동일성을 판정할 권위가 없음)와 L4를 뺀 이유(현행 SUT가 타벤더 제품을
출력할 수 없어 도달 불가)는 각각 타당하지만, 그 결과 **헤드라인이 세 문제 중 하나만 재고 있다.**

## 4. 해야 할 일

| 계층 | 현재 | 필요한 것 |
|---|---|---|
| **L2** | 25,184쌍이 "정답 미확정"으로 holdout | 형제 모델 중 정답을 **확정할 제3 권위**(벤더 제품 카탈로그·주문번호 매핑)를 붙여 양성 라벨로 승격, 또는 "기권이 정답"인 **abstain-correct** 지표로 따로 채점 |
| **L3** | 3,348쌍 채점 중 (유일하게 측정됨) | `L3-notation` 2,289 음성을 별도 슬라이스로 분리해 표기 정규화 효과를 단독 측정 |
| **L4** | 4,249쌍이 전부 음성, 도달 불가로 제외 | **양성 L4**를 만들어야 함 — Advantech WebAccess처럼 같은 제품의 분할 ID(`webaccess` / `advantech_webaccess` / `broadwin:webaccess`)를 정답 집합으로 묶은 쌍 |

특히 L4는 지금 **양성이 0건**이라 "식별자 불일치를 풀었다"를 보일 수 없다.
docs/L2_L3_L4_CANONICAL_CASES.md의 Advantech 사례가 그 양성 라벨의 원형이다.
