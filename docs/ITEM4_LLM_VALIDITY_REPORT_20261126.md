# V2 / V3 LLM 타당성 평가 — 2026-11-26

이 문서는 최초 Nemotron 개발 감사 기록이다. 후속 실제 Qwen 실측과 라벨 감사는 [Qwen 보고서](ITEM4_QWEN_LABEL_E2E_REPORT_20261126.md)를 참조한다.

구현은 완료했으나 **독립적인 의미 정확도와 현장 악용 판단 정확도는 아직 입증되지 않았다.**
아래 수치는 실제 모델 출력에 대한 개발 표본의 구조 검증 결과이며 정확도 점수가 아니다.

## 구현한 흐름

V1의 잠정 자산 유형 → V2의 CVE description 기반 조건·논리 추출 → V3의 자산 맥락을 고려한 질문·확인 방법 생성 → V4의 결정론적 조건 평가이다.
CVSS 공통 질문은 코드가 선택한다. V3는 원문과 V2 조건, 자산 유형, 이미 선택된 공통 질문을 함께 받는다.
자산 유형은 운영 기록의 맥락이며 새로운 악용 전제조건을 만드는 근거가 아니다.

V3 질문에는 고정된 긍정 사실이 포함된다. 마지막 마침표를 물음표로 바꾸는 표기만 허용한다.
조건 ID, 사실, 대상, 원문 인용, 범위, AND/OR/NOT 관계는 바꾸지 않는다.
조건이 없으면 모델 호출을 건너뛰고, 생성이 실패하면 그 조건은 Unknown으로 남긴다.
별도로 훈련한 최신 V3 어댑터가 있는 것처럼 표시하지 않는다.

**H200 결과를 웹 기본 Qwen 모델의 성능으로 전용할 수 없다.**
Qwen의 현 프롬프트에 대한 독립 의미 정확도는 미측정이다.
기존 V2 어댑터의 과거 평가 실패·실험적 사용 상태를 이번 결과로 통과 처리하지 않았다.
데이터는 경계 동작을 살피기 위해 고른 개발 표본이며, 프롬프트·검증 보완에도 사용했다.
학습 데이터와의 중복 배제, 대표 표본 추출, 독립 현장 정답 검증은 수행하지 않았다.

## 발견한 문제와 반영한 보완

1. **불확실성 연결 오류**: `unknowns`와 `uncertainty_details.reason`을 다른 문구로 작성했다.
   정확한 문자열 연결을 명시하고, 검증 오류를 포함한 한 번의 전체 재생성을 허용했다.
2. **근거 없는 불필요 조건 추론**: CVE-2016-5743의 ‘remote attackers’만 보고 인증·사용자 상호작용 불필요를 추론했다.
   불필요 조건에도 명시적 원문 근거를 요구한다. 보완 출력은 해당 추론을 제거하고 정보 부재를 Unknown으로 남겼다.
3. **이중 부정**: 합성 NOT 사례에서 `configuration_required`의 값을 disabled로 둔 뒤 NOT을 붙였다.
   모든 조건 유형에 긍정 원자 규칙을 적용했다. 표적 재실행은 `FTP is enabled`와 NOT을 반환했다.
4. **질문 표기 문제**: V2 문장 끝의 마침표를 질문의 물음표로 바꾼 것을 오류로 처리했다.
   고정 사실 필드는 그대로 유지하면서 종결 부호만 허용한다. 기록 종류의 내부 키는 화면에서 읽기 쉬운 이름으로 표시한다.
5. **V3 실행·캐시 문제 예방**: V1/V2 완료 후 큐에서 생성하며, 조회나 입력 계획 구성에서 V3를 실행하지 않는다.
   원문·조건·자산 맥락·프롬프트가 바뀌면 이전 생성 결과와 답변을 무효화한다. 실패 사유·원시 출력·모델 정보도 보존한다.

## 남아 있는 의미상의 한계

**CVE-2020-15782는 실패 사례이다.** 원문에 102/tcp 접근이 명시됐지만,
초기 보완 출력은 구체적으로 확인할 수 없는 ‘특정 동작’을 추가 조건으로 생성해 거부됐다.
표적 재실행에서도 근거 없는 불필요 조건 추론이 남아 최종 검증에서 실패했다.
안전하게 거부됐다는 사실과 유효한 접근 조건까지 복구하지 못한 누락을 모두 기록했다.

**CVE-2018-13806은 추가 의미 검토가 필요하다.** 디렉터리 쓰기 접근, 더 높은 권한의 사용자,
프로젝트 열기 동작이 추출됐으나, 사용자의 권한 조건과 열기 동작을 분리하면 ‘동일 사용자’라는 관계를 잃을 수 있다.
원자 수나 AND 구조만 맞는 것으로 이 관계의 정확성을 보증할 수 없다.

질문이 운영 기록을 가리킨다고 해서 그 기록만으로 사실을 증명할 수 있는 것은 아니다.
ACL은 전체 도달성을, 운영 절차서는 실제 악성 파일 열기나 공격자 권한을 단독으로 입증하지 못한다.
추가 기록으로 확인되지 않으면 Unknown을 유지해야 한다.

자산 유형을 제공했지만, 자산 유형을 제거하거나 바꾼 비교 실험은 하지 않았다.
**현재 결과는 자산 맥락 기반 LLM 생성이 단순 템플릿보다 낫다는 증거가 아니다.**
운영자 실험과 독립 전문가의 조건·논리·주체 관계 검토가 다음 검증 단계이다.
