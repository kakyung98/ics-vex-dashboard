# 문제 정의 재검토 — 슬라이드의 L2/L3/L4 정의 ↔ 실제 측정 기준

슬라이드에 적힌 정의를 그대로 놓고, 지금까지의 측정이 그 정의를 재는지 다시 확인한 결과.
**결론: 1차 측정(`tools/measure_l2l3l4.py`, CVE 단위)은 단위를 잘못 잡았다.**

---

## 1. 정의가 말하는 측정 단위

| 계층 | 슬라이드 정의 | 정의가 가리키는 단위 |
|---|---|---|
| L2 | "**동일·유사 명칭**의 제품 및 컴포넌트명 모호성" | 이름이 닮은 **컴포넌트** |
| L3 | "**버전 표현 불일치**, CVE 영향 버전 범위와 **빌드/패치 조건**의 모호성" | (컴포넌트, CVE) **쌍** |
| L4 | "S/HBOM과 CVE DB 간 **제조사명, 제품명, CPE/PURL** 등 식별자 불일치" | 식별자를 가진 **컴포넌트** |

세 정의 모두 **"S/HBOM 컴포넌트 → CVE DB" 매핑의 실패 양상**이다.
따라서 단위는 CVE가 아니라 **컴포넌트**(L2·L4) 또는 **(컴포넌트, CVE) 쌍**(L3)이다.

## 2. 1차 측정이 틀린 지점

| 축 | 1차 측정 기준 | 무엇이 틀렸나 |
|---|---|---|
| L2 | "동일 벤더가 앵커하는 NVD 제품이 2개 이상인 CVE" = 34.5% | **CVE가 제품 216종에 걸쳐 있는 것은 모호성이 아니라 그 CVE의 사실**이다. 모호한 쪽은 "내 컴포넌트가 그중 어느 것이냐"이고, 그건 컴포넌트 단위에서만 잴 수 있다. |
| L3 | "버전 경계·정확버전이 모두 없는 CVE" = 6.2% | 정의의 **"버전 표현 불일치"**(SBOM 측 표기)와 **"빌드/패치 조건"** 두 축이 아예 빠져 있었다. 잰 것은 "CVE 영향 버전 범위" 한 축뿐. |
| L4 | "어드바이저리 벤더와 맞는 CPE 벤더가 없는 CVE" = 34.1% | 정의는 **제조사명·제품명·CPE/PURL** 세 가지를 명시하는데 **제조사명 한 축**만 쟀다. 게다가 3,651건(31.6%)은 "실제로 서드파티 컴포넌트에 신고된 CVE"로, **식별자 불일치가 아니라 신고 대상이 다른 것**이다. |

> 즉 1차 표의 34.5% / 6.2% / 34.1%는 **정의와 다른 것을 센 숫자**다. 슬라이드에 쓰면 안 된다.

## 3. 정의대로 다시 잰 값

모집단: 역생성 SBOM 컴포넌트 **29,792건** / 어드바이저리 CVE **11,550건**

### L2 — 컴포넌트명 모호성 (단위: 컴포넌트)

| 지표 | 값 | 등급 |
|---|---:|---|
| 식별 기권율 (이름으로 제품을 확정하지 못함) | **44.0%** (6,241/14,173) | 실측 |
| └ Mitsubishi Electric | 76.3% | 실측 |
| └ Schneider Electric | 45.6% | 실측 |
| └ Siemens | 31.7% | 실측 |
| └ AutomationDirect·JTEKT·FESTO·NXP·Hikvision 등 | 100% | 실측 |
| 이름 유사도만으로 확정된 매칭 | **0건** (채점 TP 경로는 전부 `model-number`) | 실측 |

판정 기준: `identify_product()`가 후보는 있으나 1위와 2위의 유사도 격차가 임계 미만이어서
기권한 경우 = "동일·유사 명칭" 모호성. 후보가 아예 없는 경우는 모호성이 아니라 부재(L1).

### L3 — 버전 적용성 (정의의 세 축을 각각)

| 정의의 축 | 지표 | 값 | 등급 |
|---|---|---:|---|
| **버전 표현 불일치** | 기계적으로 순서 비교가 불가능한 버전 표기<br>(`6.1\|SP1\|SP2`, `>=CPR9-SR1`, `<7.1_2013.05.30`) | **2,123 / 22,413 = 9.5%** | 실측 |
| **CVE 영향 버전 범위** | 버전 경계·정확버전이 모두 없어 판정 불가한 CVE | **715 / 11,550 = 6.2%** | 실측 |
| | 버전 경계가 없는 CVE (정확버전 열거로 판정은 가능) | 2,189 / 11,550 = 19.0% | 실측 |
| **빌드/패치 조건** | 조치가 **mitigation**(설정·망 분리 등)이라 버전 비교로 표현 불가 | **8,131 / 10,791 = 75.3%** | 실측 |
| | `vendor_fix`인데 수정 버전이 **자연어로만** 기재 | 4,914 / 10,791 = 45.5% | 실측 |
| | `vendor_fix`인데 수정 버전 표기 자체가 없음 | 1,273 / 10,791 = 11.8% | 실측 |
| | 수정본 없음 (`none_available` + `no_fix_planned`) | 1,117 / 10,791 = 10.4% | 실측 |

> **정정**: 앞서 인용한 "순수 dotted version 32건(0.1%)"은 *표기 다양성*의 지표이지
> *비교 불가능성*의 지표가 아니다. `vers:intdot/<4.3.4`나 `>=9|<=9.21`은 기계 비교가 된다.
> L3의 "버전 표현 불일치"에 해당하는 값은 **9.5%**다.

### L4 — 식별자 불일치 (정의가 명시한 식별자 종류별)

| 정의의 식별자 | 지표 | 값 | 등급 |
|---|---|---:|---|
| **CPE** | CSAF OT 제품 중 CPE 보유 | 47 / 28,631 = **0.16%** | 실측 |
| **PURL** | CSAF OT 제품 중 purl 보유 | **0건** | 실측 |
| **PURL** | 역생성 SBOM의 purl이 표시명을 슬러그화한 **자리표시자**<br>(`pkg:generic/cisco-richards-zeta-mediator-2500-vers-all@NOASSERTION`) | 100% | 실측 |
| **제조사명** | 어드바이저리 벤더 ↔ CPE 벤더 불일치 중 **동일 회사·다른 ID** | 288 CVE (2.5%) | 실측 |
| | 〃 중 실제 서드파티 컴포넌트 신고 (= 불일치가 아님) | 3,651 CVE (31.6%) | 실측 |
| | NVD 내부에 같은 회사가 두 벤더 ID로 존재 | 8쌍 | 실측 |
| **제품명** | 같은 제품 라인이 복수 NVD 제품 ID로 분할, CVE 집합 교집합 0 | Advantech WebAccess **4분할**, GE CIMPLICITY 2분할 등 | 사례 |
| | 〃 자동 스크리닝 후보 (ICS 벤더, 펌웨어 관례 제외) | 3,073쌍 (**상한**) | 프록시 |

> 제조사명 축에서 3,651건을 L4로 세면 안 된다. Siemens 장비에 Linux CVE가 붙는 것은
> **식별자가 틀린 게 아니라 신고 대상이 임베디드 컴포넌트인 것**으로, 별개의 문제(범위/계층)다.

## 4. 슬라이드에 쓸 숫자 (권장)

| 계층 | 숫자 | 한 줄 |
|---|---|---|
| **L2** | 식별 기권 **44.0%**, 이름만으로 확정 **0건** | 형제 모델이 이름으로 안 갈린다 |
| **L3** | 표현 불일치 **9.5%** · 범위 부재 **6.2%** · 조치가 설정뿐 **75.3%** | 버전 비교로는 닿지 않는 조건이 대부분 |
| **L4** | CPE 보유 **0.16%** · purl **0건** · 제품 ID 분할 교집합 **0** | 불일치 이전에 식별자가 없다 |

## 5. 재현

```bash
python tools/measure_l2l3l4_components.py   # results/l2l3l4_components.json (컴포넌트 단위)
python tools/measure_sbom_cpe_limits.py     # results/sbom_cpe_limits.json
python tools/eval_cpe_match_precision.py    # results/cpe_match_precision.json (기권율)
```

`tools/measure_l2l3l4.py`(CVE 단위)의 출력은 **정의와 단위가 어긋나므로 슬라이드에 쓰지 않는다.**
참고용으로만 남긴다.
