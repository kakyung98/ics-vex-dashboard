# 시험 항목 4 CSAF 시나리오와 전문가 검증 설계

> 실제 실행 추가: 70% 무라벨 학습 및 12,418개 CVE 전체 v2 모델 평가가 완료되었습니다. 데이터 manifest의 training_executed=false는 생성 당시 스냅샷이며, 현재 실행은 [실제 결과](ITEM4_V2_ACTUAL_RUN.md)와 actual_run_status.json을 확인합니다. 전문가 판정은 미실시입니다.

2026년 11월 20일 개정. 대상은 ICSA 3,881건에서 연결한 CVE 12,418개 전체이다. 다섯 CSAF 비영향 사유와 영향 있음·근거 부족 대조군으로 CVE당 7개, 총 86,926개 합성 사례를 구성한다. 성능 지표는 기존 affected 정밀도 TP/(TP+FP), 통과 기준 85% 초과를 유지한다.

## 1. 모집단과 분할

ICSA를 먼저 학습 2,717건, 전문가 검증 1,164건으로 분할한다. seed는 20261120이며 발행 연도와 선언 CVE 유무를 층화하고 최대 잔여 방식으로 1,164건을 정확하게 배분한다. 합성 사례 생성 후 사례별 무작위 재분할은 하지 않는다.

모든 12,418개 CVE에 7개 사례를 배정한다. 평가 ICSA에 한 번이라도 연결된 CVE는 평가 측에 두고, 여러 평가 ICSA와 연결되면 정렬 순서의 첫 ICSA를 대표 집계 단위로 삼는다. 따라서 전문가 검증 대상은 4,090개 CVE·28,630개 사례이고 나머지는 8,328개 CVE·58,296개 사례이다. 평가 ICSA 13건은 연결된 목표 CVE가 없어 advisory_index에 별도 남긴다. CVE를 만들어 채우거나 ICSA를 제외하지 않는다.

학습·평가 ICSA에 동시에 등장하는 CVE는 889개이다. 원문·CVE 중복 내역을 split_overlap_audit.json에 공개한다. 이 분할은 ICSA 단위 홀드아웃이며 CVE 단위 미노출이나 기저 모델 사전학습 미노출을 보장하지 않는다. 같은 CVE의 사례를 학습용 정답으로 사용하는 일은 없다.

## 2. 정답 없는 학습

training/corpus.jsonl의 2,717개 text를 causal language modeling에 사용한다. 공급사 원문의 제목·설명·일반 문맥을 수록하며 생성한 상태·사유 정답, 후보 라벨, 전문가 판정, 평가 측 원문은 넣지 않는다. CSAF의 product_status와 flags를 학습 정답으로 사용하지 않는다. 모델은 입력 텍스트의 다음 토큰을 예측하고 모든 유효 토큰에 자기지도 손실을 계산한다. 기존 assistant-completion 지도학습과 별개이다.

평가용 1,164건을 학습, early stopping, 프롬프트 수정 또는 체크포인트 선택에 사용하지 않는다. 별도 학습용 파일럿에서 지침을 정하고 본 평가 전에 동결한다. corpus 준비와 실제 GPU 학습 완료는 구분한다. 현재 배포 가중치는 이 개정으로 자동 변경하지 않는다.

## 3. 시나리오의 성립 논리

평가 단위는 CVE·제품·빌드·구성·시점이다. 출처의 제품·버전·조건 경로와 원문 인용을 연결하고, 그 위에 가상 제품 증명 자료를 부여한다. 원문 사실과 합성 사실을 별도 필드로 보존한다. 합성 증명은 실제 공급사의 발표나 실제 설치 관측이 아니다.

합성 세계의 상태는 컴포넌트 존재 C, 취약 코드 존재 V, 실행 경로 E, 공격자 제어 A, 유효 내장 방어 M이다. 닫힌 가상 세계 안에서 영향 조건은 C AND V AND E AND A AND NOT M이다. 누락된 값은 unknown이다. 한 가지 비영향 사유를 고립시키기 위해 선행 조건은 참, 해당 차단 조건은 거짓 또는 내장 방어 참, 후속 무관 조건은 unknown으로 둔다. 이 식은 생성용 독립 오라클이며 실제 CVE의 완전한 악용식을 발견했다고 주장하지 않는다.

- component_not_present: 완전한 제품 구성·배포 범위에서 CVE 관련 컴포넌트 C가 없음. SBOM 미기재만으로 인정하지 않는다.
- vulnerable_code_not_present: C는 있지만 해당 빌드의 취약 코드 V가 없음. 컴포넌트 부재와 구분한다.
- vulnerable_code_not_in_execute_path: C·V가 있지만 모든 평가 제품 상태에서 E가 없음. 방화벽·단일 출발점의 접속 실패는 실행 경로 증명이 아니다.
- vulnerable_code_cannot_be_controlled_by_adversary: C·V·E는 있지만 악용에 필요한 A가 불가능함. 현재 운영자의 권한 부재만으로 판정하지 않는다.
- inline_mitigations_already_exist: C·V·E·A는 있지만 제품 내장 방어 M이 해당 악용을 차단함. 외부 망 분리·운영 절차는 이 사유가 아니다.
- affected_control: C·V·E·A가 참이고 M이 거짓인 충분한 가상 근거를 부여한다.
- insufficient_evidence: 불완전한 목록만 제공하고 빌드·경로·제어·방어 근거는 제공하지 않는다.

조건 경로를 연결한 CVE는 4,899개이다. 나머지 CVE에도 모든 사례를 생성하지만 컴포넌트 부재의 조건부 가정 외에는 CVE별 관계를 발명하지 않고 후보 정답을 unknown으로 둔다. 후보 true 4,899건, false 32,014건, unknown 50,013건이다. 경로 완전성은 합성 세계의 명시적 가정이며 원문이 이를 입증한 것으로 취급하지 않는다. 내부 분석을 운영자가 새로 수행하도록 요구하지 않고, 빌드·제품별 공급사 자료가 없으면 미확정으로 남긴다.

## 4. 입력과 정답의 분리

inputs.jsonl은 제품·가상 근거·명시적 가정만 포함한다. ID는 의도 라벨을 포함하지 않는 해시이다. source_evidence_ref로 원문과 선택 경로를 추적한다. sboms는 제품 식별 참조 목록이며 실제 설치 확인 목록이 아니다. 컴포넌트 부재 사례의 완전한 구성 확인은 별도 가상 증명 문서로 제공한다.

candidate_labels.jsonl은 생성 의도와 독립 오라클의 후보 정답이다. gold.jsonl은 전문가 검증 전 전건 미확정이다. review/packets는 후보 라벨·fold·잠재 상태를 제외한 맹검 패킷이다. 전문가에게 candidate_labels와 candidate_csaf_vex를 제공하지 않는다. 상태와 사유가 문서의 의미에서 추론되는 것은 평가 내용이며, 의도 라벨을 메타데이터로 노출하지 않는다.

CSAF 2.0은 known_not_affected와 flags.label·product_ids를 연결한다. 설명은 threats의 impact에 둔다. affected는 known_affected, 미확정은 under_investigation으로 표현한다. 모든 합성 문서는 draft이며 publisher를 합성 벤치마크로 표시한다. 전문가 확정 전의 최종 내보내기는 미확정이며 후보 문서를 승격하지 않는다.

## 5. 전문가 검증과 Cohen의 κ

두 전문가는 같은 평가 사례 28,630개를 독립 판정한다. 검토 대상은 출처 연결, 합성 논리, 근거 충분성, 영향 상태, 다섯 사유의 성립 여부이다. reviewer_id, 인용 근거, 판정 이유, 시점을 기록한다. 본 평가 전에 학습 측 파일럿으로 지침을 확정한다. 생성 의도, 모델 출력과 상대 판정은 숨긴다.

영향 상태는 affected / not_affected / under_investigation이다. actual_affected는 각각 true / false / null이다. 사유·출처·논리·충분성은 yes / no / unknown으로 기록한다. 한 사례에서 복수 사유가 성립하면 모두 기록할 수 있다. 확정 상태에는 출처·논리·근거 충분성이 모두 yes여야 한다. 자료가 불충분하면 전문가도 보류할 수 있다.

조정 전 최초 판정으로 비가중 Cohen의 κ = (Po-Pe)/(1-Pe)를 계산한다. Po는 관측 일치율, Pe는 두 평가자의 주변 라벨 분포에서 계산한 우연 일치율이다. 상태 κ, 사유별 κ 5개, 출처·논리·충분성 κ와 단순 일치율·혼동행렬을 보고한다. 대표 ICSA 단위 1,000회 cluster bootstrap으로 95% 신뢰구간을 계산한다. 동일 CVE의 여러 사례를 독립 표본으로 간주하지 않는다.

프로젝트 제안 게이트는 상태 및 사유별 κ 각각 0.80 이상이다. 보편적인 인증 기준은 아니다. 판정 쌍 미완료, 빈 표본, 주변 분포가 단일 범주여서 κ가 정의되지 않는 경우는 통과로 처리하지 않는다. 본 평가를 본 뒤 지침을 바꾸면 새로운 버전에서 재평가하며 이전 불일치를 숨기지 않는다.

이후 불일치 또는 최초 일치 판정의 변경은 제3 전문가가 조정한다. 원래 두 판정은 보존한다. 조정 후 라벨로 κ를 다시 계산해 신뢰도를 높여 보고하지 않는다. 최종 골든은 해당 합성 자료의 의미 검증 결과이고 실제 자산 영향 검증이 아니다.

## 6. 성능 지표와 보고 범위

기존 지표를 유지한다. TP는 시스템 affected·골든 true, FP는 시스템 affected·골든 false이다. 정밀도는 TP/(TP+FP)이고 엄격히 0.85 초과해야 한다. 정확히 0.85, affected 0건은 통과가 아니다. 골든 unknown에 affected를 출력한 사례는 별도 집계하고 전체 정밀도와 통과 판정을 보류한다. 재현율·보류율·사유별 결과는 보조 지표이다. not_affected 정밀도로 주지표를 교체하지 않는다.

전 모집단 조건부 합성 기준선과 전문가 표본 성능을 별도로 보고한다. 70% 문맥 측에는 전문가 정답이 없으므로 30% 검증만으로 전 모집단 전문가 정확도를 확정하지 않는다. full population 지표에 미검토 정답을 임의로 채우지 않는다. 기존 7-CVE·991건의 89.86%는 과거 규칙 기준선으로만 보존하며 이번 성능으로 인용하지 않는다.

## 7. 구현 경계와 재현

생성기는 tools/build_item4_csaf_benchmark.py, 독립 오라클·κ·기존 지표는 src/item4_benchmark_v2.py, 검토·조정·점수·CSAF 내보내기는 tools/item4_expert_review.py, 전수 무결성·공식 스키마 감사는 tools/verify_item4_csaf_benchmark.py이다. 과거 full_population 파일과 배포 Agent 3·4의 제품 비영향 정책을 덮어쓰지 않는다. 새 벤치마크의 합성 증명은 운영 시스템의 실제 증거로 주입하지 않는다.

모델 예측은 86,926개 ID 모두를 갖춘 JSONL이어야 한다. 실행 실패도 under_investigation으로 남기며 사례를 삭제하지 않는다. 예측 파일을 닫은 후 정답을 읽어 채점한다. 생성 코드·출처·입력·정답·공식 스키마의 해시를 보존하고 ZIP에 포함 파일 해시를 기록한다. 현행 GPU 모델·MulVAL 전체 실행은 별도 실행 기록으로 입증한다.
