# #4 1단계: ICSA-CVE 악용조건 추출 및 검증 설계

현재 기본 실행은 [사람 라벨링이 필수가 아닌 자동 4단계 경로](ITEM4_AUTOMATIC_PIPELINE.md)다. 아래 사람 검토 필수 정책은 이전 수동 경로에만 적용한다.
작성일: 2026-11-16 KST. 상태: 설계 및 1차 구현. 실행법은 [실행 안내](ITEM4_STAGE1_RUNBOOK.md)를 참고한다. 계약·원문 어댑터·후보·검토 승인·평가·H200 실행 도구를 구현했다. 학습·독립 의미 정확성 검증의 완료를 주장하지 않는다. 아래 수동 검토/의미 평가 계획에는 아직 수행하지 않은 작업이 포함된다.

## 1. 목적과 단계 경계

ICSA 및 CVE 원문이 뒷받침하는 악용조건을 CVE·제품·기능 범위에 묶어 추출한다. 최우선 원칙은 **원문 근거가 없는 조건을 확정 추출하지 않는 것**이다. 인용이 실제로 존재하는 것과 그 인용이 필수조건을 뒷받침하는 것은 서로 다른 검증이다.

1단계는 조건과 원문의 관계만 확정한다. 공격 그래프 구성·AND/OR 확정은 2단계, 자산 운영 정보 필드 정의는 3단계, 실제 자산의 VEX 판단은 4단계다. 원문에 있는 관계 표현은 인용으로 보존하되, 1단계가 그래프나 VEX 상태를 자동 생성하지 않는다. 조건이 비어 있어도 악용 불가능이나 전체 경로 검토 완료를 뜻하지 않는다.

## 2. 입력: 불변 원문과 명시적 범위

실행 전에 원천 목록과 모집단 버전을 고정한다. 입력은 다음 세 종류를 분리한다.

| 입력 | 필수 내용 | 처리 원칙 |
| --- | --- | --- |
| 원문 문서 | source_id, URL, 수집 시점, 원문 바이트 SHA-256, 파서 버전 | HTML/CSAF/CVE JSON 등 원본을 보존한다. 문서 갱신은 새 버전이다. |
| 텍스트 구간 | segment_id, 원문 JSON pointer 또는 DOM 위치, 추출 텍스트, 텍스트 SHA-256 | 인용 위치는 불변 추출 텍스트에 대한 Python Unicode code point 인덱스다. 원본 바이트 해시와 혼용하지 않는다. |
| 적용 범위 | 명시된 CVE ID, product_scope_id, 제품명·버전·기능, 연결 근거 | 구조화 CVE/제품 참조 또는 명시적 문구로 연결한다. 같은 문서에 등장했다는 이유만으로 연결하지 않는다. |

ICSA 공통 서문·완화 권고와 CVE별 본문을 분리한다. 공통 본문은 advisory 범위로 보관하고, 개별 CVE 귀속의 근거가 없으면 조건으로 승격하지 않는다. CVE 전용 본문이어도 여러 영향 제품 중 어느 제품에 적용되는지 불명확하면 범위 미확인으로 남긴다. 버전 범위를 임의 설치 버전으로 바꾸지 않는다.

제품 매뉴얼 등은 용어·기능 설명 자료로 분리한다. 매뉴얼에 기능이 있다는 사실만으로 특정 CVE의 필수조건을 만들지 않는다. 추가 공급자 보안 공지 등을 사용할 때에는 해당 CVE·제품에 대한 연결을 별도로 기록한다. CVSS 벡터 자체를 운영조건으로 변환하지 않는다. CVE 레코드의 설명문은 다른 원문과 동일한 기준으로 검토한다.

원문은 문장·문단·절 단위로 나누고 제목·앞뒤 문맥·범위 참조를 보존한다. 긴 문서의 중첩 윈도와 원문 위치 대응을 기록한다. 지시어가 다른 문단을 참조하면 관련 구간을 함께 제시한다. 문맥을 가져오지 못하면 미확인으로 남기며, 길이 제한으로 잘린 문서를 전체 검토 완료로 표시하지 않는다.

## 3. 무엇을 추출하고 무엇을 승격하지 않는가

| 역할 | 예시의 의미 | 확정 필수조건으로 사용 |
| --- | --- | --- |
| necessary_condition | 서술된 악용 경로에 필요한 접근·상태·권한·행위 | 원문 필요성·대상·범위의 의미 검증 후 가능 |
| explicit_nonrequirement | 인증 없이 가능하다는 명시 | 별도 사실로 보존. 인증 기능 비활성화나 계정 부재로 바꾸지 않음 |
| conditional_context | 특정 상황에서 가능하다는 서술이나 필요성 불명확 | 불가. 검토 후보로 보존 |
| trigger | 특수 입력 전송·파일 열기 등 트리거 | 트리거로 보존. 그 자체를 모든 경로의 필수조건으로 승격하지 않음 |
| impact | 코드 실행·정보 유출·서비스 중단 | 불가 |
| mitigation | 패치·차단·기능 비활성화 권고 | 불가. 권고를 뒤집어 필수조건으로 만들지 않음 |
| applicability | 영향 제품·버전·플랫폼 | 범위 정보로 보존 |
| observed_context | 특정 시연·시험에서 관측된 환경 | 불가. 유일한 악용 환경으로 취급하지 않음 |

필요성 판단은 키워드 하나로 결정하지 않는다. 예를 들어 `only when`도 문맥과 대상이 맞아야 하며, `if`만으로 필요성을 확정하지 않는다. `can exploit by X`는 설명된 X 경로의 트리거를 뒷받침할 수 있지만 X가 전체 CVE의 유일 경로라는 뜻은 아니다. 부정·예외·권한 수준·기능명·조건절을 인용에 포함한다.

명시된 공격자 인증·권한은 실제 조건이면 보존한다. 운영자가 확인하기 어렵다는 이유로 삭제하지 않으며, 운영자 관측 가능성 판단은 3단계로 넘긴다. 정상 사용자 계정의 존재가 공격자의 계정 보유를 증명하지 않는다.

정규화는 표현을 정리하는 데 제한한다. 원문보다 강한 주장, 상세 서비스·포트 추정, 신규 CWE 부여, 자산 유형에서의 접근성 추정은 금지한다. 사전에 맞는 predicate가 없으면 `unmapped`와 원문 표현을 유지한다.

## 4. 출력 계약

출력은 문서 처리 결과, 구간 후보, 조건 주장, 검증 기록을 분리한다. 아래는 구현할 논리 계약이며 기존 API와 동일한 형식이라는 뜻은 아니다.

| 객체 | 핵심 필드 |
| --- | --- |
| 처리 결과 | run_id, contract_version, extractor/model_version, source_manifest_hash, 처리 segment 목록, 처리 실패·누락 |
| 구간 후보 | candidate_id, role, evidence_refs, CVE/제품 귀속 후보, ambiguity_reasons |
| 조건 주장 | claim_id, predicate, target, required_value, 원문 기반 necessity_scope, CVE/제품 범위, condition_evidence, binding_evidence |
| 검증 기록 | 인용·무결성 결과, 범위 결과, 의미 판정, reviewer/method/version/time, 판정 이유·근거 |
| 미해결 목록 | 주장·범위·출처 충돌, 누락 문맥, 처리 실패, 해결에 필요한 자료 |

각 evidence_ref는 source_id, segment_id, start, end, quote, segment_sha256을 포함한다. `text[start:end] == quote`를 검사한다. 필요성을 지지하는 구간과 CVE·제품 귀속을 지지하는 구간은 분리할 수 있다. 제목 등 복수 구간이 함께 의미를 지지하면 모두 참조한다.

의미 검증에서 다음 항목을 각각 `supported / unsupported / ambiguous`로 판정한다.

1. 이 인용이 정규화된 조건의 내용을 지지하는가?
2. 이 내용이 서술된 경로의 필수조건인가?
3. CVE·제품·기능 범위가 정확한가?
4. 한정어·부정·예외를 보존했고 출처 간 충돌은 없는가?

현재 v1 계약의 `necessity_scope`는 `described_path`로 제한한다. 필요성·범위가 미확인이면 주장 상태를 unresolved로 두고 승인하지 않는다. 원문이 모든 경로의 공통조건이라고 설명하더라도 그 표현을 인용으로 보존하고, `all_paths` 승격과 포괄성 검증은 2단계에서 별도 구현한다. 필드의 이름이나 리뷰 승인만으로 경로 포괄성을 증명하지 않는다.

확정 조건은 원문 무결성·인용·적용 범위 검증을 통과하고, 위 의미 검토가 모두 supported이며 미해결 충돌이 없어야 한다. 초기 버전의 확정 승격은 원문 기반 사람 검토를 거친다. 자동 의미 검토기는 보조 판정이며 사람 승인 필드를 생성할 수 없다. 독립 정확성 평가 이전에 자동 승격을 활성화하지 않는다.

보존 상태는 `candidate / accepted / rejected / unresolved`로 구분한다. rejected도 삭제하지 않고 이유를 남긴다. 별도 모델의 동의는 `accepted`를 대신하지 않는다. 원문 변경 시 기존 승인 적용을 중지하고 새 버전을 재검토한다.

문서 처리 상태는 주장 상태와 별도로 관리한다.

- `processed_with_candidates`: 후보가 발견됨. 정확성 승인이나 전 경로 포괄성을 뜻하지 않음.
- `processed_no_candidate`: 모델이 후보를 찾지 못함. 조건이 없다는 정답이 아님.
- `reviewed_no_explicit_condition`: 사람이 지정 원문 범위를 모두 검토했지만 명시적 필수조건을 확인하지 못함. CVE에 조건이 없다는 뜻은 아님.
- `source_unavailable / parse_failed / inference_failed / partial / scope_unresolved`: 이유와 영향 범위를 기록.

모든 결과는 `vex_eligible=false`, `coverage_complete=false`로 2단계에 전달한다. accepted는 해당 주장에 대한 승인이지, 실제 VEX 발행 승인이나 공격 경로 전체의 완전성 승인이 아니다.

## 5. 모듈 구성과 실행 순서

```text
source_adapter → immutable_source_bundle → scope_resolver
  → span_extractor → claim_normalizer → integrity_and_scope_validator
  → semantic_review → accepted_claim_export
```

| 모듈 | 책임 | 실패 시 |
| --- | --- | --- |
| source_adapter | ICSA CSAF·CVE JSON 등 원문과 위치를 보존 | 원천 실패로 기록; 가공 텍스트 임의 생성 금지 |
| scope_resolver | 명시적 CVE/제품 참조를 연결 | 미귀속 후보 유지; 문서 전체에 자동 확산 금지 |
| span_extractor | 원문 구간과 역할 후보 추출 | 실패와 빈 예측을 구분 |
| claim_normalizer | 인용으로 지지되는 속성만 정규화 | 채울 수 없는 속성은 null/unmapped |
| integrity_and_scope_validator | 해시·위치·인용·참조·범위 검사 | 자동 보정 대신 거절/미해결 |
| semantic_review | 조건 내용·필요성·범위·누락 독립 검토 | 검토 사유와 반대 근거 보존 |
| accepted_claim_export | 승인 주장과 출처·미해결 사항을 함께 출력 | 미해결을 제거한 완전한 그래프로 포장 금지 |

BERT/LLM 선택과 무관하게 동일 계약을 적용한다. BERT의 BIO 역할 예측도 필요성·제품 귀속을 확정하지 않는다. 추출·검토 프롬프트는 원문을 지시가 아닌 비신뢰 데이터로 취급한다. LLM confidence는 승인 근거가 아니다.

## 6. 구현 검증: 결정적 자동 검사

다음 검사를 단위/통합 테스트로 구현한다. 이는 알고리즘의 계약 준수 검사이며 독립 의미 정확도 측정과 구분한다.

| 검사군 | 필수 사례와 기대 결과 |
| --- | --- |
| 원문 무결성 | 해시 불일치, 잘못된 위치, 인용 변조, 원문 갱신 → 기존 근거 불수용 |
| 문자 위치 | 한글·이모지·반복 인용 → code point 및 occurrence 혼동 없이 원문 재현 |
| 범위 | 같은 ICSA의 다른 CVE·다른 제품 조건, 공통 완화 문구 → 자동 승격 차단 |
| 역할 | 결과·완화·시연 환경·explicit nonrequirement → 필요조건 자동 변환 차단 |
| 의미 한정 | 부정·예외·조건절·권한 수준 누락 → 승인 불가 또는 미해결 |
| 긴 문서 | 윈도 경계의 조건절·지시어, 중복 윈도 → 문맥 복구·중복 제거 또는 partial |
| 실패 | 파싱 실패·문맥 초과·모델 실패·빈 예측 → 각각 기록, 비영향 변환 금지 |
| 모델 계약 | 잘못된 JSON·없는 predicate·없는 source ID·원문 내 지시문 → 불수용 |
| 출처 충돌 | 수정 공지와 이전 공지가 상충 → 버전별 보존과 검토, 조용한 최신값 덮어쓰기 금지 |

역할 오인·필요성 오인은 문자열 검사만으로 완전히 검출할 수 없다. 자동 테스트에는 고정된 사람 검토 사례를 사용하고, 자유로운 새 원문의 의미 보장은 독립 평가로 확인한다. 인용을 보정해 맞추거나 다른 출처의 유사 문장을 몰래 대체하지 않는다.

## 7. 독립 의미 검증과 평가 데이터

### 7.1 Gold 작성

실제 원문에 대해 두 검토자가 모델 출력을 보지 않고 독립 라벨링한다. 역할 구간뿐 아니라 조건 내용·필요성·CVE/제품 귀속을 표시한다. 불일치는 근거와 함께 조정하고, 해소되지 않는 사례는 ambiguous Gold로 보존한다. 전체 범위를 검토한 경우에만 음성 Gold를 허용한다. 합성 문장·LLM 출력·기존 자동 초안은 실제 정확성 Gold를 대신하지 않는다.

다중 CVE, 다중 제품, 원문 부족, 부정·예외, 복수 출처 상충, 긴 문서, 권한/설정/파일/네트워크 조건과 실제 음성 문서를 포함한다. 초기 파일럿은 100개 원문 묶음을 제안하며, 규모는 라벨 분포와 검토 부담 확인 후 확정한다. 파일럿 결과로 본 평가 표본 크기와 기준을 사전 고정한다. 의도적으로 어려운 사례를 모은 진단 세트와 모집단에서 추출한 평가 표본은 분리 보고한다.

전체 목표 CVE 12,418개의 처리 원장은 유지한다. 수동 평가가 표본이면 표본 범위·선정 방식·미검토 수를 밝힌다. 원문이 빈약한 CVE를 제외해 성능을 높이지 않는다.

### 7.2 분할과 누출 방지

ICSA와 CVE 공유 관계의 연결 성분을 기준으로 train/dev/test를 분리한다. 동일 원문·수정본·근접 중복·번역·동일 공급자 보안 공지의 재게시가 경계를 넘는지 감사한다. 분리 불가능한 대형 성분을 임의 분할하지 말고 규모와 처리 방식을 보고한다. 제품/벤더 단위 일반화 평가는 별도로 둔다. 모델·정규화 규칙·프롬프트·합격 기준을 고정한 뒤 보류 test를 평가한다.

### 7.3 보고할 지표

| 지표 | 정의/해석 |
| --- | --- |
| 인용·무결성 통과율 | 자동 계약 검사. 의미 정확도와 구분 |
| 정확 구간 및 역할별 Precision/Recall/F1 | 필요조건뿐 아니라 완화·결과 등 혼동 보고 |
| 역할 κ와 검토자 간 κ | O 비중·분포·혼동행렬 동시 보고. 모두 O 등 정의 불가 시 null |
| 조건 주장 Precision/Recall | 올바른 의미·CVE/제품 범위까지 일치한 주장. 중복 주장은 1회만 매칭 |
| 근거 없는 필수조건 비율 | 의미 미지지·범위 오귀속·필요성 과장의 합집합 / 출력 필수조건 수. 원인별 분해 |
| 미확인 필요성 출력 비율 | Gold도 미해결인 주장을 별도 보고. 정확/부정확에 임의 배정하지 않음 |
| 조건 누락률 | Gold 필수조건 중 회수하지 못한 비율. 빈 예측도 포함 |
| 오귀속률 | 다른 CVE·제품·경로 범위로 잘못 연결한 주장 비율 |
| 처리·검토·승격률 | 전체 입력/후보/검토/승인/미해결 수와 분모를 함께 보고 |

추출 후보와 승인 결과의 지표를 각각 보고해 사람 검토가 모델 오류를 가리지 않게 한다. 후보 단계의 근거 없는 출력도 집계한다. Claim 평가의 매칭 기준은 정규화된 의미·대상·값·부정·범위에 대한 일대일 정답 매칭으로 고정하고, 애매한 매칭은 독립 검토한다. 인용 F1 하나로 대체하지 않는다.

소스/권고문 단위로 묶은 신뢰구간과 오류 건수를 함께 보고한다. 같은 문서의 여러 조건을 독립 표본으로 과대 계산하지 않는다. 관측 오류 0건을 모집단 오류 0%의 증명으로 표현하지 않는다.

### 7.4 통과 조건

원문 해시·정확 인용·유효 참조·검토 기록·범위 근거는 승인 레코드의 필수 계약이다. 누락 시 다음 단계에 확정 조건으로 전달하지 않는다. 의미 Precision/Recall·근거 없는 추출률의 수치 기준은 파일럿 후 본 평가 전에 정한다. 이 문서는 임의 목표치를 이미 달성한 것처럼 기재하지 않는다.

범위/필요성에 대한 알려진 오승격은 회귀 사례로 등록하고 해결하기 전 해당 패턴의 자동 승격을 허용하지 않는다. 현재 초기 설계는 사람 검토 승격 방식이며, 자동 승격은 별도 변경·검증 대상이다.

기존 서비스·예전 결과를 교체하지 않는다. 새 구간/주장 계약과 Vulntology 초안 계약은 형식이 다르므로, 향후 연결할 때 원문 참조·구간 역할·범위를 손실 없이 보존하고 표현할 수 없는 주장은 미해결로 남긴다. 새 CLI와 H200 격리 실행은 서비스 배포와 별도다.

구현 순서:

1. 버전별 입력/출력 JSON Schema, 상태 전이, 원천 manifest 계약 구현.
2. 불변 원문 패킷·범위 어댑터와 무결성 회귀 테스트 구현.
3. 실제 원문 파일럿 Gold 작성·불일치 분석, 평가 기준 확정.
4. 기존 구간 추출기에 주장 정규화·검토·승인 export 연결.
5. 고정 test로 독립 평가하고 전체 모집단 처리 상태를 보고.
6. 2단계에 승인 조건·원문 근거·미해결 사항을 함께 전달.

예정 산출물은 버전별 계약, source manifest, 후보 JSONL, 승인 주장 JSONL, 미해결/거절 원장, 독립 Gold, 평가 보고서와 오류 사례다. 아직 생성되지 않은 파일을 완료 산출물로 표시하지 않는다.
