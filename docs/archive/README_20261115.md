### 웹 #4 데이터와 VEX 판단 범위

18개 자산 타입은 탐색용 후보입니다. 6,170개 CVE에 제품별 자산 후보가 연결되고 6,248개는 자산 미확정 그룹에 남아 있습니다. 같은 자산 타입이라는 이유로 공통 필수조건을 부여하지 않습니다. 벤더 제품 ID와 CISA 제품 ID도 자동으로 동일시하지 않습니다.

최초 규칙 기반 초안 보유 CVE 4,855개에, 최초 미추출 대상 7,563개의 벤더 자료 보완으로 184개 CVE·395개 경로·154개 질문이 추가되어 현재 웹 수량이 되었습니다. 벤더 참조 미선정, 접근·CVE 구간 미확인, 본문 해석 미해결, 철회된 CVE 식별자 문제를 별도로 기록합니다. **초안 없음은 필수조건 부재나 비영향의 증거가 아닙니다.** [벤더 보완 결과](results/item4_missing_vendor_review_v1/supplement/summary.json)를 참조하세요.

운영자는 제품·원문 경로의 의미를 검토한 후 실제 자산·실행 빌드·구성·운전 모드·공격 출발점·평가 시점을 지정하고, 질문에 예·아니오·모름과 관측 근거를 연결합니다. 정보 부족·충돌은 `under_investigation`으로 남깁니다. 알려진 조건식이 참이라는 이유만으로 `affected`를 만들거나, 방화벽 차단만으로 `not_affected`를 만들지 않습니다.

NIST Vulntology의 native 구조와 프로젝트의 조건식·질문·관측 메타데이터를 분리합니다. 필수 native 필드의 출처별 의미 검토와 고정 스키마 검증이 성립해야 native 내보내기를 허용합니다. 필수 항목이 없는 부분 초안은 완전한 native Vulntology나 검증된 VEX 결과가 아닙니다.

### LLM 평가: 준비된 표본과 미완료 검증

현재 전수 실행의 `benchmark/`에 `protocol.json`, `source_packets_for_annotation.jsonl`, `annotation_blank.jsonl`, `annotation_guidance.json`을 저장했습니다. 같은 CISA 권고문 연결 그룹을 분할 사이에 나누지 않고, 예제가 존재하는 자산 타입·자산 미확정·벤더 자료가 부족한 사례를 포함합니다. 현재 자산 분류에서 예제가 없는 A0012는 정답 사례를 만들어 채우지 않습니다. 벤더 제품군·유사 원문의 분할 누출은 추가 점검이 필요합니다.

두 명의 독립 검토자가 모델 예측을 보기 전에 원문에서 조건과 시나리오를 주석한 뒤 불일치를 조정하는 절차입니다. 평가 항목은 조건 precision·recall·F1, 근거 없는 필수조건 주장, 조건 누락, 부정·AND/OR, CVE·제품 범위, 질문의 운영자 답변 가능성·의미·극성, unknown 보존과 처리 실패율입니다. 최종 시험 예측으로 프롬프트를 조정하지 않으며 실패·자료 부족·빈 출력도 평가 대상에 남깁니다. 주석과 판정이 갖춰진 후 `tools/score_llm_scenario_adjudications.py`로 조건 매칭 점수와 권고문 그룹 부트스트랩 구간을 계산합니다. 이 조건 점수만으로 질문·native 필드·VEX 정확도를 확정하지 않습니다.

**독립 전문가 주석은 아직 없으므로 실제 CVE의 의미 정확도는 측정 전입니다.** 개발용 합성 진단에서는 선택한 8B 설정이 16건 중 12건, 비교한 14B 설정이 16건 중 10건을 통과했습니다. 이는 사용한 프롬프트·양자화·런타임 설정의 개발 진단이며 모델 전체의 우열이나 독립 정확도가 아닙니다. 파일럿에서는 조건 오해, 코드 분석·내부 메모리 상태를 요구하는 질문, 이미 공격이 발생했는지를 묻는 질문도 발견됐습니다. 모든 LLM 결과는 의미 검토 대기이며 `vex_eligible=false`, `native_export_ready=false`로 보관합니다. 상세 비교는 전수 실행 폴더의 `evaluation_summary.json`을 참조하세요.

## 공인시험 #3·#4 성능 지표

기존 프로젝트에서 참조한 기준 문서는 `전남대(260921)_공인시험 항목#3,4.hwp`입니다. 현재 체크아웃에는 해당 원문이 없어 아래 기준은 기존 정리 기록이며 원문 복원 후 재대조가 필요합니다. 기존 기록에서 두 항목의 주 지표는 **정밀도 = TP / (TP + FP) × 100**입니다.

| 구분 | #3 SBOM 기반 공개 취약점 정보 식별 정밀도 | #4 VEX 기반 식별된 취약점 영향 판단 정밀도 |
| --- | --- | --- |
| 평가 대상 | SBOM 구성요소에 매핑한 CVE | VEX에서 Affected로 자동 판정한 항목 |
| TP | SBOM의 CPE·해시 정보와 외부 DB의 CVE가 정확히 일치하는 매핑 | Affected로 판정했고 실제 자산의 버전·패치 여부·실행 컨텍스트가 CVE 영향 조건과 일치하는 사례 |
| FP | 잘못된 제품 매핑 또는 버전·에디션 불일치 | Affected로 판정했으나 실제 환경에서 영향 없음이 확인된 사례 |
| 합격 기준 | **80% 이상** | **85% 이상** |

#3은 CVE 매핑의 정확성을 평가하며 실제 운영 영향 여부를 고려하지 않습니다. #4는 Affected 판정의 정밀도이며 전체 VEX 상태의 정확도나 비영향 판정의 정확도와 다릅니다. 재현율·기권율·판정 범위는 별도 보조 지표입니다. TP+FP가 0이면 정밀도는 정의되지 않습니다.

미확정 출력이 있으면 판정 가능한 출력의 정밀도, 미확정 건수와 판정 범위를 함께 표시합니다. 기존 #3 평가기는 미확정 출력이 있으면 전체 정밀도를 확정하지 않으며, 미확정을 모두 오답으로 간주한 보수적 하한도 별도로 제공합니다. 원문에는 미확정 처리 규칙이 없으므로 보조 지표를 공인시험 합격과 동일시하지 않습니다.

원문과 현행 구현 사이에는 다음 차이가 남아 있습니다.

- 기존 Word 시험절차서 생성기 `tools/build_procedure_docx3.py`에는 #3 기준이 95%로 남아 있습니다. 원문 기준은 **80% 이상**입니다.
- #4 원문은 소스코드 수집 가능·불가 분기를 전제하지만 현재 구현은 운영맥락 전용입니다. 현행 시험 범위와 절차의 정리가 필요합니다.

## #3 최신 데이터셋

현재 데이터셋은 **`data/item3_spelling_noise_v10`**입니다. CISA ICS-CERT 참조 CVE 12,418개 중 NVD CPE 기록이 있는 **10,847개 전체**를 대상으로 합니다. CISA 제품명과 NVD CPE의 직접 이름 일치를 추가 제외 조건으로 사용하지 않습니다. v9의 원본 조건·정답·학습/평가 분할은 유지하면서, 다른 제품·버전·CPE를 주입하던 사례를 **동일 항목의 오타·표기 차이**로 수정했습니다.

### 구축 방식과 수량

CVE에 연결된 제품·버전 조건을 추출한 뒤, 여러 CVE에서 동일하게 반복되는 조건은 하나로 묶습니다. **조건을 합쳐도 연결된 CVE는 모두 정답에 유지합니다.** 예를 들어 제품 X 2.0이라는 같은 조건에 CVE A·B·C가 연결되면, 기준 SBOM은 하나를 만들고 정답 CVE에는 A·B·C를 모두 기록합니다.

조건의 중복 제거 기준은 **CPE 문자열(`criteria`)과 네 버전 경계 값의 조합**입니다. 경계 값은 `versionStartIncluding`(이상), `versionStartExcluding`(초과), `versionEndIncluding`(이하), `versionEndExcluding`(미만)이며, 없는 값은 미지정으로 유지합니다. 같은 CPE라도 “3.0 미만”과 “4.0 미만”은 서로 다른 조건입니다. 따라서 고유 조건 50,860개는 서로 다른 제품 50,860종이라는 뜻이 아닙니다.

각 조건마다 **구성요소 하나를 담은 기준 SBOM 1개**와 **제품명·버전·CPE 중 한 항목에 누락 또는 오타·표기 차이를 넣은 SBOM 1개**를 생성합니다. 여기서 구성요소 하나는 제품·소프트웨어 항목 하나를 뜻합니다. 실제 설비 전체를 수집한 SBOM이 아니라 개별 구성요소의 CVE 매핑을 측정하는 합성 입력입니다.

| 분류 | 개수 | 정의 |
| --- | ---: | --- |
| 대상 CVE | 10,847 | CISA ICS 권고문에서 참조한 CVE 중 NVD CPE 기록이 있는 CVE |
| 고유 CPE 문자열 | 40,660 | 대상 CVE에 연결된 CPE 문자열을 중복 제거한 수 |

| 고유 CPE·버전 범위 조건 | 50,860 | CPE 문자열과 네 버전 경계 값이 동일한 기록을 하나로 묶은 조건 수 |
| 기준 SBOM | 50,860 | 조건마다 오류를 추가하지 않은 기준본 1개 |
| 오류 주입 SBOM | 50,860 | 조건마다 한 필드 계열에 누락 또는 같은 항목의 오타·표기 차이를 넣은 오류본 1개 |

오류 주입본에는 누락과 오타·표기 변형이 함께 있으므로 전체를 “마스킹 SBOM”이라고 부르지 않습니다. 기준본 역시 원본에 미확정 속성이 남을 수 있으므로 “정상본” 대신 “오류를 추가하지 않은 기준본”으로 표현합니다. 오류 유형의 균등 배정은 실험 설계이며 실제 현장의 오류 발생 비율을 의미하지 않습니다.

### 노이즈 선택 기준

에이전트의 목적은 **같은 제품·버전·CPE의 입력 오류를 복구하는 것**입니다. 다른 제품이나 실제 다른 버전을 정답으로 간주하도록 바꾸지 않습니다.

| 단계 | 허용한 노이즈 | 예시 |
| --- | --- | --- |
| P2 제품명 | 대소문자, 공백/밑줄, 앞뒤 공백, 인접한 영문 두 글자의 순서 오타 | `viewer pro` → `Viewer pro`, `viewer_pro`, `ivewer pro` |
| P3 버전 | 원본 버전 문자열 앞에 `v`, `Version ` 또는 `version ` 추가. 원래 버전 값 전체 유지 | `1.2.3` → `v1.2.3`, `Version 1.2.3` |
| P4 CPE | CPE 접두어의 대소문자·인접 글자 오타·공백. 제품·버전을 포함한 11개 속성 문자열은 전부 유지 | `cpe:2.3:…` → `CPE:2.3:…`, `cep:2.3:…`, `cpe: 2.3:…` |

노이즈 선택에는 랜덤 함수를 쓰지 않습니다. 조건 ID와 단계의 해시로 허용된 변형 중 하나를 선택하므로 같은 원본과 코드로 재현됩니다. P2 글자 순서 오타가 원본 모집단의 다른 제품명과 일치하면 해당 후보를 제외합니다. P3 숫자를 바꾸거나 P4를 다른 제품의 CPE로 대체하는 후보는 만들지 않습니다. 변형 전후 값과 적용 규칙은 정답 측 별도 기록에 저장하며 모델 입력에는 넣지 않습니다. 이 단순 노이즈 범위의 성능을 모든 현장 오기입에 대한 성능으로 일반화하지 않습니다.

이전 v6/v7의 **44,567개 기준 사례·89,134개 SBOM**은 대표 버전 선택 후 같은 구성요소를 합친 결과입니다. v9부터 대표 버전이 같더라도 원본 CPE·버전 범위 조건이 다르면 유지해 **50,860개 기준 사례·101,720개 SBOM**을 생성합니다. v10은 이 수량을 유지하고 노이즈 방식만 수정합니다. 대상 CVE 수가 늘어난 것이 아니라 생성 단위가 달라진 것이므로 이전 수량과 혼용하지 않습니다.

### 분할·정답과 검증

7:3은 CVE 기준입니다. 각 조건의 기준본과 오류본은 같은 분할에 속하고, 오류는 P2 제품명·P3 버전·P4 CPE 중 한 필드 계열에만 주입합니다. P2가 한 개 더 많은 것은 3등분 후 남은 한 개를 P2부터 배정하기 때문입니다. 생성 여부는 `build_status.json`, 수량은 `counts.json`, 원본·정답 보존과 단일 필드 변경의 전수 검증 결과는 `validation_audit.json`을 기준으로 합니다.

버전 근거가 부족한 조건 4,853건은 미확정으로 보존합니다. `vulnerable:false` 플랫폼 기록을 양성 CVE 정답으로 승격하지 않습니다. v10의 표기 변형 사례는 동일 항목의 정규화와 CVE 매핑을 평가하며, 이전 v9의 다른 항목 주입에 대한 충돌 탐지 평가와 구별합니다. 정답 CVE는 모델 입력에 넣지 않습니다.

**v10 기준 모델 재학습·성능 평가는 아직 수행하지 않았습니다.** 이전 전용 실행기와 성능을 v10에 그대로 적용하지 않습니다. 정답은 고정 NVD 원본으로 계산한 합성 기준값이며 실제 자산 적용성을 독립 전문가가 검증한 정답은 아닙니다. 수량·분할·재생성 방법은 [v10 데이터셋 문서](docs/ITEM3_SPELLING_NOISE_V10.md)를 참조하세요.

## 모델과 설정

이 절의 기본 모델·추론 설정은 #3 식별 런타임과 이전 학습 이력에 관한 내용입니다. 현재 #4 LLM 전수 추출은 상단의 llama.cpp/GGUF 실행 설정과 별도입니다. 아래의 과거 문장 단위 추출 준비 명령은 현재 전수 실행의 재개 명령이 아닙니다.

2026-11-11 모델 설정 점검: 현재 LLM 기본 모델은 로컬 `ICS-VEXForge/models/Qwen3-8B`이며 학습은 4비트 NF4·이중 양자화 QLoRA를 사용합니다. 조건 추출 도구에 남아 있던 14B 기본 경로도 Qwen3-8B로 변경했습니다. 조건 추출 기본 배치는 1이며, 새 문장 단위 추출 결과는 `results/ics_sentence_conditions_qwen3_8b_v1`에 저장하여 이전 14B 캐시와 분리합니다. 당시 문장 단위 추출의 준비 명령은 `python tools/run_sentence_conditions.py --prepare`였습니다. 기존 사전 검사 통과 조건은 유지되며, 8B로 변경했다는 사실은 의미 정확도 검증을 뜻하지 않습니다. 기존 학습·평가 결과와 어댑터 가중치는 그대로 보존합니다. 식별 학습 도구의 기본 배치는 1, 누적은 8이며, v10 학습의 원문 보존 및 입력 길이 검증은 유지합니다.

실제 RTX 4070 Ti SUPER에서 입력 1,024토큰·배치 1·rank 8·체크포인팅으로 QLoRA의 순전파, 역전파, optimizer 업데이트 1회를 검증했습니다. 최대 PyTorch 할당은 약 8,263MiB, 예약은 10,850MiB였습니다. 결과는 `results/qlora_8b_memory_smoke.json`에 기록했으며, 합성 입력 1회 검사는 전체 재학습 완료·장기 안정성·업무 정확도의 증거가 아닙니다.

기본 식별 모드는 `data/identification_runtime.json`의 `agents`입니다. #3은 **Parsing → Orchestrator의 조건부 라우팅 → 필요한 P2/P3/P4 → Decision Validator → CVE Matching**으로 실행합니다. `src/identification_routing.py`의 LangGraph `StateGraph`가 제품명 누락·모호성은 P2, 버전 누락·표기 차이·충돌은 P3, CPE/PURL 누락·불일치는 P4로 보냅니다. 여러 문제가 있으면 필요한 역할을 순서대로 실행하며, 구조화 근거가 충분하면 에이전트를 생략합니다. P3 후 후보를 다시 검색하고 조건을 재평가합니다. P2가 실행됐다면 P4와 최종 검증기는 P2가 실제로 검토한 후보만 허용합니다. 모든 경로는 원본·사전 근거를 독립 검증하며, 필요한 에이전트의 실패를 규칙 결과로 조용히 대체하지 않습니다. 구성요소별 `routing`에 실행·생략 사유와 실제 경로를 기록합니다. 실제 자산에 대한 독립 정확도는 확립되지 않았습니다.

공유 Hybrid RAG는 구조화 CPE/제품/제조사 조회, BM25, 문자 3-gram TF-IDF 벡터 코사인 검색을 RRF로 결합합니다. 현재 벡터 인덱스는 **문자 기반 희소 벡터**이며 의미 임베딩 모델을 사용하지 않습니다. 검색 점수는 식별 확정 근거가 아닙니다.

세 역할은 하나의 Qwen3-8B 기본 가중치를 공유하며, 현재 기본 추론 경로는 식별용 LoRA 어댑터를 적용하지 않습니다. 4비트 NF4·이중 양자화와 BF16 연산으로 로드하고, Transformers/PyTorch 및 `icsvex_efficient_sdpa`를 사용합니다. 생성은 `do_sample=False`의 greedy 방식이며 JSON 스키마로 허용 토큰을 제한합니다. 입력 한도는 6,144토큰, 최대 생성은 768토큰입니다.

후보 검색은 BM25와 문자 3-gram 검색을 RRF로 결합합니다. P3는 근거에 있는 버전 관측을 분류하고 규칙 코드가 표기·범위를 처리하며, P2는 검색된 사전 후보를 재정렬합니다. P4는 규칙·사전 검증을 통과한 후보와 모델 선택이 일치할 때만 확정합니다. 현재 P4는 임의의 CPE 오타를 자유 생성으로 수정하는 모델이 아닙니다. 오타·표기 복구라는 시험 목적에 맞춘 데이터셋 수정과 실제 에이전트의 복구 성능 검증은 별개이며, v10 기준 학습·평가가 남아 있습니다. 별도 역할 어댑터를 사용하는 `TrainedIdentificationRuntime`은 실험 평가 경로이며 기본 웹 추론 경로와 구별합니다.

웹의 `Rules · comparison baseline` 또는 API `agent_mode: "rules"`로 규칙 비교를 실행할 수 있습니다. 환경변수 `ICSVEX_IDENTIFICATION_MODE=rules`는 전역 규칙 비교를 지정합니다. `tools/benchmark_item3_l234.py`는 이전 규칙 경로의 실행기입니다.

효율형 SDPA와 짧은 후보 ID 전송을 사용하며 원본 ID는 복원 후 다시 검증합니다. 실행 중 GPU lease로 학습·평가·웹 추론의 중복 점유를 조정합니다. 배치 처리량과 단일 웹 요청 지연 시간은 구분합니다.

현재 웹 #4의 시나리오·질문·판정은 `src/asset_vulntology.py`와 `src/asset_vulntology_api.py`가 처리하고, `src/asset_vulntology_page.py`·`src/asset_vulntology.html`·`src/asset_vulntology_ui.js`가 화면에 연결합니다. `src/item4_review.py`, `src/fixed_operational_questions.py`, `data/operational_runtime_models.json`, `models/vex-writer-qwen3-8b-v1`은 이전 검토·질문·작성 경로의 호환/연구 이력이며 이 설정만으로 새 #4의 현재 동작을 판단하지 않습니다. 별도 LLM 전수 추출은 `src/llm_scenario_extraction.py`와 `tools/run_full_population_llm_scenarios.py`를 사용하며, 결과는 현재 웹에 자동 반영하지 않습니다.


화면 생성은 외부 배포를 수행하지 않습니다. 위 명령은 현재 #4·LLM 출력 검증기·클라우드 실행기의 동작 검사이며, 테스트 통과는 GPU 추론의 의미 정확도나 실제 자산 VEX 정확도를 입증하지 않습니다. GPU 추출은 별도 상태 파일, 독립 정확도는 주석·판정 후 평가 결과를 확인합니다. 과거 2026-11-11에 `test_operational_only.py`, `test_web_evidence_review.py`, `test_item3_source_conditions_v9.py`의 33개 테스트가 통과한 기록은 이전 경로의 검사 이력입니다.
