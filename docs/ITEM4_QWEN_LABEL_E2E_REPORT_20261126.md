# #4 Qwen 실측·라벨 감사·전체 흐름 검증

## 결론

현재 방식의 참조 라벨과 실제 Qwen 평가 결과를 만들었다. **독립적인 전문가 정답셋과 현장 악용 정답은 완성되지 않았다.**
현재 V2는 원문 조건을 누락하며, 형식 검증 통과를 의미 정확도로 제시할 수 없다.
V3는 고정 조건을 질문으로 표현하는 검증을 통과했지만, V2가 놓친 조건을 복구하는 검증은 아니다.
실험적인 기존 모델 설정을 유지했으며 이번 작은 표본으로 어댑터를 통과 처리하거나 기본 모델로 자동 전환하지 않았다.

## 라벨링 상태

| 자료 | 규모 | 실제 의미 |
|---|---:|---|
| 기존 BOM 주석 | 3,881개 | 과거 합성 질문 시나리오. 현재 CVE 조건·최종 악용 정답 아님 |
| 기존 V2 학습 | 50건 | 실제 원문 42건 + 합성 8건, assistant 라벨 |
| 기존 V2 시험 | 82건 | 실제 원문 18건 + 합성 64건, assistant 라벨 |
| 현재 계약 참조 라벨 | 82건 | 기존 시험 라벨을 원문·조건·논리·질문 요건 형태로 이관·검토·고정 |
| V2 조건 라벨 | 67개 | 부분 조건과 미확정 관계도 보존 |
| V3 질문 대상 라벨 | 64개 | 조건식에서 실제 참조되는 조건. 나머지 후보 3개는 자동 질문으로 승격하지 않음 |
| 독립 전문가 정답 | 0건 | 실제 원문 18건의 검토 대기 파일 제공 |
| 실제 운영 환경 악용 정답 | 0건 | `actual_exploitable=null` 유지 |

실제 18건은 기록된 어댑터 학습 42건과 출처 그룹 및 원문 텍스트가 겹치지 않는다.
그러나 과거 개발·평가 및 기반 모델 사전학습 노출은 배제하지 못한다.
이번 감사에서 사례를 보며 검증기를 보완했으므로 미사용 블라인드 시험이나 모집단 정확도로 표시하지 않는다.
참조 정답은 모델 입력으로 보내지 않았고, 모델은 원문·스키마·현재 맥락만 받았다.

참조 파일은 `benchmark/item4_evaluation/current_reference_v1/`에 있다.
원문 해시, 라벨 해시, 작성 방식, 전문가 검토 미완료 상태를 함께 저장했다.
독립 정답 채점기는 이 assistant 참조를 독립 전문가 정답으로 받아들이지 않는다.

과거 학습 라벨 `CVE-2023-0345`는 SSH의 기본 활성 상태를 필수 악용 조건으로 승격했다.
현재 보수적인 기준에서는 재검토가 필요하므로 `legacy_training_label_issues.jsonl`에 기록했다.
원래 학습 데이터·가중치를 수정하거나 새 전문가 라벨로 위장하지 않았다.

## 실제 웹 모델 평가

동일한 실제 원문 18건으로 Qwen2.5-Coder-14B의 현재 추출 어댑터와 어댑터를 끈 기반 모델을 비교했다.
V3는 실제 웹과 같은 기반 모델을 사용한다. 어댑터 해시와 기반 가중치 해시는 각 실행 manifest에 있다.

| 측정 | 현재 V2 어댑터 | 기반 모델 비교 |
|---|---:|---:|
| 실제 원문 | 18건 | 18건 |
| 구조 수용 | 18건 | 10건 |
| 실패 | 0건 | 8건 |
| 실제 특수 질문 생성 사례 | 1건 | 4건 |
| 조건 없음으로 V3 생략 | 17건 | 6건 |
| 엄격한 원자·인용 일치 TP / FP / FN | 0 / 1 / 7 | 0 / 4 / 7 |

엄격한 일치는 인용 범위·구조 필드 차이에도 실패한다. 따라서 이 숫자를 의미 정밀도·재현율로 해석하지 않는다.
예를 들어 현재 어댑터는 OSPF 활성 상태를 복구했지만 정답과 인용 절의 범위가 달랐다.
그럼에도 다른 명시적 조건들을 비워 두는 누락이 확인돼 구조 수용 18/18을 정상 성능으로 볼 수 없다.

기반 모델은 Basic128Rsa15, 초기 설정 대기 모드, OSPF, WDB 에이전트 상태를 표현했다.
하지만 초기 설정 모드를 `interface_reachable`로 잘못 분류한 출력과 검증 실패도 있었다.
조건이 더 보인다는 사실만으로 기반 모델의 전체 정확도가 높다고 결론 내리거나 자동 교체하지 않았다.

V3 단독 평가는 실제 원문 참조 4건과 AND/OR/NOT 합성 통제 3건, 총 10개 고정 조건으로 수행했다.
**실제 Qwen 출력 7건 모두 고정 사실 보존 검증을 통과했다.**
이는 운영자 사용성, 기록의 충분성, 자산 유형 제공의 효과 또는 V2 누락 복구의 증명이 아니다.
V2 조건이 없어 건너뛴 호출을 V3 성공으로 집계하지 않았다.

18건의 원 실행은 검증 정책 7에서 기록됐다. 기본 상태와 객체 범위 문제를 보완한 후
최종 문제 사례 재실행과 실제 BOM 검증은 최신 정책으로 별도 기록했다. 원 실행 결과를 덮어쓰지 않았다.

## 수정한 문제

- 불확실성 문구 끝의 마침표만 다른 경우, 유일한 원래 사유에 연결한다. 다른 의미의 사유를 합치지 않는다.
- 한 번의 재생성에 발견된 검증 오류들을 함께 전달해 한 오류만 고치고 다른 오류를 남기는 문제를 줄였다.
- 사용자 동작에는 동일 행위자의 권한 한정어를 보존하도록 지시·검증했다.
- 공격자의 디렉터리 쓰기 권한을 파일 쓰기 가능 여부나 임의 사용자 권한으로 대체하는 출력을 거부한다.
- 질문은 실제 운영 사실이어야 한다. ‘악용하려면 반드시 …해야 한다’라는 규칙 자체를 입력 사실로 받지 않는다.
- 별도의 기본 설정 설명을 악용 조건의 극성으로 사용하지 않는다. 기본 비활성을 필수 비활성 조건으로 바꾸지 않는다.
- 길이 제한 없는 불확실성 설명을 제한하고 생성에는 90초 상한을 두었다. 불완전 출력은 추정 복구하지 않는다.
- V3의 종결 부호와 기록 종류의 내부 키는 표시 형식만 정리한다. 고정 사실과 논리는 변경하지 않는다.
- 완료된 작업 안에 추출 실패가 있으면 영어 화면에 미해결 CVE 수와 재시도 안내를 표시한다.

최종 문제 사례의 실제 사실·미해결 항목은 통합 JSON의 `critical_outputs`와
`results/item4_qwen_critical_guard9_20261126/`에 있다.
**검증기가 잘못된 출력을 거부하도록 수정한 것과 모델이 빠진 조건을 안정적으로 복구하는 것은 다른 성과이다.**
특히 102/tcp 접근 같은 조건의 누락이 남아 있어 V2 의미 타당성을 확보했다고 주장하지 않는다.

## 실행과 실제 BOM 흐름

Windows에서 기본 attention 경로의 메모리 포화와 긴 응답을 관찰했다.
#4 생성 호출 동안만 메모리 효율 SDPA를 사용하고 공유 런타임의 기존 설정을 복원한다.
BF16의 인과 마스크·캐시형 마스크 3개 통제에서 기존 math SDPA와 수치 근사 일치를 확인했다.
이는 가중치 변경이나 독립적인 의미 정확도 검증이 아니다.

원격 MulVAL 도구의 이전 폴더 구조 때문에 실제 실행이 실패하는 문제도 수정했다.
기존 격리 실행 래퍼를 원래 위치에서 읽으며, 격리·자원 제한은 유지한다.
실제 MulVAL 생성 그래프에서 참·거짓·미확정이 각각 유지되고, 알려진 경로 차단이 제품 비영향 증명이 되지 않는 것을 검증했다.

사용자 원본 `출력_ics-vex-cve-candidates.json`은 식별 분석 보고서이며 표준 BOM 자체는 아니다.
웹 UI에는 식별 보고서를 BOM으로 변환하는 호환 처리도 있다. 이번 검증은 명시적인 표준 파일을 사용했다.
이전에 변환한 표준 CycloneDX의 별도 사본 `출력_ics-vex-identified.cdx.json`으로 실제 HTTP 흐름을 검증한다.
설치 버전이나 운영 설정을 임의로 만들지 않고 모든 관측값을 Unknown으로 저장한다.
분석·관측 저장·V4 평가·OpenVEX 및 CycloneDX 내보내기의 최종 실측은
`results/item4_live_bom_20261126/report.json`과 각 원본 응답에 기록된다.
실제 사용자 BOM의 11개 CVE, 그래프 11개, VEX 문장 11개를 확인했다. 모두 미확정 관측을 유지했다.
별도의 OSPF 활성 조건 시험 BOM에서는 공통 질문 1개와 실제 LLM 특수 질문 1개를 생성했고,
반복 조회 후에도 질문이 재생성되거나 계획 해시·답변 버전이 바뀌지 않는 것을 확인했다.
이 흐름의 완료는 실제 악용 가능 여부 정답의 확보를 뜻하지 않는다.
